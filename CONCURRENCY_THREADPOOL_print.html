线程池 · 原理、实现与嵌入式落地

文档定位：线程池 = 一条任务队列 + 一组常驻工作线程。读完本册你应能给任意项目手写一个最小可用的线程池，并说清它在实时系统里该放在哪、不该放在哪。

前置：《队列与生产者-消费者》册。线程池的队列部分直接复用它，本册只讲"线程数组"和"任务分发"。

体例：先给一句话结论，再展开；代码为完整可编译的最小示例，逐函数讲解；带 文件:行号 的可点开本工程源码核对。

用法：§1–§3 建模型，§4 逐函数读代码，§8 对照本工程理解"RT 线程为什么要配线程池"。

§1 为什么需要线程池

一句话结论：线程的创建/销毁很贵，且数量必须可控；线程池用"一次创建、反复复用"把这两件事一起解决。

表 1-1　不用线程池的三个问题
问题说明
创建开销大每次任务都 pthread_create，要分配栈、注册内核结构；任务短时，创建的时间比干活还长。
数量失控任务一多就无限建线程，CPU 在大量线程间切换，缓存全废，反而更慢甚至耗尽资源。
无法限流没有统一入口，出了问题（雪崩、卡死）时无从下手控制并发。

线程池的做法：启动时固定创建 N 个工作线程，它们阻塞在任务队列上等着；有新任务就从一个统一入口丢进队列，某个空闲线程被唤醒后取走执行。线程始终复用，数量恒定可控。

§2 线程池的组成

一句话结论：线程池就是"队列 + 线程数组 + 一个关闭标志"。把《队列》册的结构拿来当任务队列，再加一个线程数组即可。

表 2-1　线程池的五个部件
部件作用
任务队列存放待执行的任务（队列版复用它，通常用链表，因为任务大小不定）
工作线程数组N 个常驻线程，循环"取任务 → 执行"
互斥锁保护任务队列和计数器
条件变量队列空时工作线程睡眠，来任务时被唤醒
关闭标志shutdown，让工作线程知道该退出了
一个任务长什么样：任务 = 一个函数指针 + 一个参数。调用方把"要做什么"包成 void (*fn)(void*) 和 arg 提交，工作线程只管调用它，不关心里面是什么业务——这就是线程池的通用性来源。

§3 工作流程

一句话结论：提交者只入队，工作线程只出队执行；中间靠条件变量"来活了就喊一声"。

提交者线程pool_add(fn, arg)
→ 入队 + signal →
任务队列任务链表
→ 取走一条 →
空闲工作线程被唤醒
▼
执行 fn(arg)业务逻辑
→ 做完 →
回到等待再睡回条件变量

关键点：工作线程永远在做三件事的循环——加锁检查队列是否为空 → 空就睡在条件变量上 → 不为空就取一条解锁执行。执行期间不持锁，所以多个工作线程能真正并行干活。

§4 完整实现（pthread 最小可用版）

一句话结论：一个链表任务队列 + N 个跑同一段 worker 循环的线程。

/* ---- threadpool.h ---- */
#include <pthread.h>
#include <stdlib.h>
#include <stdbool.h>

typedef struct task {
    void          (*fn)(void *arg);   /* 任务函数 */
    void           *arg;              /* 任务参数 */
    struct task    *next;             /* 链表下一条 */
} task_t;

typedef struct {
    pthread_mutex_t  lock;        /* 保护下面所有字段 */
    pthread_cond_t   has_task;    /* 有任务时唤醒工作线程 */
    task_t          *head, *tail; /* 任务链表 */
    pthread_t       *threads;     /* 工作线程数组 */
    int              nthreads;    /* 线程数 */
    int              ntasks;      /* 队列中待处理任务数 */
    int              shutdown;    /* 0 运行 / 1 立即关 / 2 温和关 */
} pool_t;

int  pool_add(pool_t *p, void (*fn)(void *), void *arg);
pool_t *pool_create(int nthreads);
void pool_destroy(pool_t *p, int graceful);
/* ---- threadpool.c ---- */

/* 工作线程主体: 循环"取任务 → 执行" */
static void *worker(void *arg) {
    pool_t *p = arg;
    for (;;) {
        pthread_mutex_lock(&p->lock);
        /* 队列空且未关闭 → 睡; 被唤醒后必须重查(while) */
        while (p->head == NULL && !p->shutdown)
            pthread_cond_wait(&p->has_task, &p->lock);

        /* 退出条件: 立即关, 或温和关且已无任务 */
        if (p->shutdown == 1 || (p->shutdown == 2 && p->head == NULL)) {
            pthread_mutex_unlock(&p->lock);
            break;
        }

        /* 摘一条任务, 然后立刻解锁再执行(执行不持锁!) */
        task_t *t = p->head;
        p->head = t->next;
        if (p->head == NULL) p->tail = NULL;
        p->ntasks--;
        pthread_mutex_unlock(&p->lock);

        t->fn(t->arg);              /* 干活: 此时不持锁, 可并行 */
        free(t);
    }
    return NULL;
}

/* 提交任务: 任何线程都能调 */
int pool_add(pool_t *p, void (*fn)(void *), void *arg) {
    task_t *t = malloc(sizeof *t);
    if (!t) return -1;
    t->fn = fn; t->arg = arg; t->next = NULL;

    pthread_mutex_lock(&p->lock);
    if (p->shutdown) {                     /* 已关闭, 拒收 */
        pthread_mutex_unlock(&p->lock);
        free(t);
        return -1;
    }
    if (p->tail) p->tail->next = t;        /* 尾插, O(1) */
    else         p->head = t;
    p->tail = t;
    p->ntasks++;
    pthread_cond_signal(&p->has_task);     /* 叫醒一个空闲线程 */
    pthread_mutex_unlock(&p->lock);
    return 0;
}

/* 创建: 预建 N 个常驻线程 */
pool_t *pool_create(int nthreads) {
    pool_t *p = calloc(1, sizeof *p);
    if (!p) return NULL;
    p->threads  = calloc(nthreads, sizeof(pthread_t));
    p->nthreads = nthreads;
    pthread_mutex_init(&p->lock, NULL);
    pthread_cond_init(&p->has_task, NULL);
    for (int i = 0; i < nthreads; i++) {
        if (pthread_create(&p->threads[i], NULL, worker, p) != 0) {
            p->nthreads = i;               /* 只记创建成功的数量 */
            break;
        }
    }
    return p;
}

/* 销毁: graceful=1 先把队列做完再退, =0 立即退 */
void pool_destroy(pool_t *p, int graceful) {
    pthread_mutex_lock(&p->lock);
    p->shutdown = graceful ? 2 : 1;
    pthread_cond_broadcast(&p->has_task);  /* 必须广播唤醒全部线程 */
    pthread_mutex_unlock(&p->lock);

    for (int i = 0; i < p->nthreads; i++)
        pthread_join(p->threads[i], NULL); /* 等所有线程真正退出 */

    /* 释放可能残留的任务节点 */
    task_t *t = p->head;
    while (t) { task_t *next = t->next; free(t); t = next; }

    pthread_mutex_destroy(&p->lock);
    pthread_cond_destroy(&p->has_task);
    free(p->threads);
    free(p);
}

4.1 逐函数讲解

表 4-1　每个函数的关键动作
函数持锁时做什么锁外做什么
worker判断/摘任务、改链表和 ntasks执行 t->fn(t->arg)（不持锁）
pool_add尾插链表、ntasks++、signal无
pool_create只做初始化，不涉及队列创建线程
pool_destroy置 shutdown、broadcastjoin 所有线程、释放内存
最容易写错的一行：worker 里必须先解锁、再执行任务。如果持着锁去执行 fn，所有工作线程就退化成串行（等于没有线程池），还可能和 fn 内部的加锁互相死锁。

§5 优雅关闭：立即关 vs 温和关

一句话结论：立即关 = 丢掉没做的任务直接退；温和关 = 把队列里的任务做完再退。用 shutdown 的取值区分（本实现 1=立即、2=温和）。

表 5-1　两种关闭的适用场景
方式场景
立即关（shutdown=1）程序要退出了，剩余任务无所谓；或需要快速停机
温和关（shutdown=2）队列里是"必须落盘/必须上报"的任务，要保证做完

无论哪种，pool_destroy 里都要 broadcast 唤醒全部工作线程（它们可能都睡着），再 join 等它们退出。先关队列、再 join、最后释放内存，顺序不能乱，否则线程还会访问已释放的对象。

§6 线程数怎么定

表 6-1　线程数的经验值
任务类型特征经验值
CPU 密集一直在算，几乎不等待≈ CPU 核数
IO 密集大量等磁盘/网络可大于核数（等待时可切换）
嵌入式常见少量低负载后台活（日志/上报）2~4 个足够

经验公式（IO 密集）：N ≈ 核数 × (1 + 平均等待时间 / 平均计算时间)。但嵌入式设备 CPU 弱、任务简单，通常 2~4 个即可，多了反而增加切换开销。

§7 常见坑

表 7-1　线程池的六个典型坑
坑后果与对策
执行任务时持锁退化成串行 + 易死锁。对策：摘出任务后立刻解锁再执行
wait 用 if 包虚假唤醒导致读到空任务而崩溃。对策：一律 while
关闭用 signal只叫醒一个，其余线程永远睡，join 卡死。对策：关闭时 broadcast
关闭后仍提交任务任务被丢弃却无人知。对策：pool_add 检查 shutdown 并返回 -1
释放顺序错先 free 对象再 join，线程访问已释放内存。对策：先关→join→再释放
任务里阻塞太久工作线程被占死，队列堆积。对策：长阻塞任务单独处理，别占池子

为什么 RT 侧必须"非阻塞入队"：工作线程池是"慢消费者"，队列是它们之间的缓冲。RT 线程 1ms 一拍、绝不能等消费者；所以用《队列》册 §5 的 queue_try_push，满了就丢并累加 dropped。实时性 > 完整性：宁可少记一条日志，也不能错过一个控制节拍。
