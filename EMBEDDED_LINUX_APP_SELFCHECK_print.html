§1 进程与线程

Q1进程和线程的本质区别？
进程是资源分配的基本单位，线程是 CPU 调度的基本单位。进程有独立地址空间；线程共享所属进程的地址空间（代码段、数据段、堆、文件描述符），但各有独立栈和寄存器。线程切换不用换页表，比进程切换轻。
自评：□ 能讲清　□ 模糊　□ 不会
Q2fork 之后父子进程的内存是什么关系？什么是写时复制（COW）？
不立即复制，靠写时复制：先共享、写时才拷。fork 时父子共享同一批物理页并标记只读，任一方写入会触发缺页异常，内核才复制那一页。所以 fork 很快，子进程改自己的变量不影响父进程。
自评：□ 能讲清　□ 模糊　□ 不会
Q3fork / vfork / exec 的区别？
fork 是复制，vfork 是共享且阻塞父进程，exec 是替换。fork 复制地址空间（COW）；vfork 与父进程共享地址空间且父进程挂起，子进程几乎立刻 exec 时用（现已少见）；exec 不创建新进程，只把当前进程映像整体换掉。fork + exec 是启动新程序的标准组合，shell 就是这么干的。
自评：□ 能讲清　□ 模糊　□ 不会
Q4wait / waitpid 干什么用？不调用会怎样？
回收子进程的退出状态和内核资源（PCB）。子进程先退出而父进程不回收，它就变成僵尸进程，一直占着 PCB。若父进程先退出，子进程被 init(1) 收养。
自评：□ 能讲清　□ 模糊　□ 不会
Q5僵尸进程和孤儿进程的区别？
僵尸是"死了没人收"，孤儿是"父先死了"。僵尸：子进程已退出但父进程没 wait，仍占 PCB，有害；孤儿：父进程先退出，子进程被 init 收养，反而能被正常回收。
自评：□ 能讲清　□ 模糊　□ 不会
Q6什么是守护进程？创建一个 daemon 的步骤？
脱离终端、后台长期运行、独立于控制终端的进程。步骤：fork 后父进程退出 → setsid() 建立新会话脱离控制终端 → 可选再 fork 使自身不是会话首进程 → chdir("/") → 把 stdin/stdout/stderr 重定向到 /dev/null。本工程的 canopend 就常以服务方式长期运行。
自评：□ 能讲清　□ 模糊　□ 不会
Q7条件变量为什么必须用 while 而不是 if 包住 pthread_cond_wait？
防"虚假唤醒"和"唤醒后条件已被抢走"。被唤醒不等于条件一定成立：可能被虚假唤醒，也可能条件刚被别人改回去。必须重新检查条件，while 保证只有条件真成立才往下走。
自评：□ 能讲清　□ 模糊　□ 不会
Q8什么是竞态条件？怎么避免？
多个执行流非原子地访问共享数据，结果依赖调度顺序。避免手段：加锁（互斥量/自旋锁）、原子操作、把共享范围降到最小、用消息传递替代共享内存。本工程位姿是"RT 线程写、主线程读"，所以用 CO_LOCK_OD 保护。
自评：□ 能讲清　□ 模糊　□ 不会
Q9死锁的四个必要条件？怎么避免？
互斥、持有并等待、不可剥夺、循环等待——破坏任意一条即可。固定加锁顺序（破循环等待）、trylock 加超时（破不可剥夺）、一次性申请全部锁（破持有并等待）、减少锁粒度。本工程主线程与 RT 线程共用 OD 锁，靠"单一加锁点"避免死锁。
自评：□ 能讲清　□ 模糊　□ 不会
Q10互斥锁、自旋锁、读写锁、信号量分别用在什么场景？
看"能不能睡"和"读多还是写多"。互斥锁：临界区可能阻塞/睡眠时用（会睡眠）；自旋锁：临界区极短且不可睡眠（如中断上下文），忙等；读写锁：读多写少，允许多读单写；信号量：计数型，能控制并发数量（不止 0/1），可用于线程也可用于进程。
自评：□ 能讲清　□ 模糊　□ 不会

§2 进程间通信（IPC）

Q11进程间通信有哪几种？各适合什么场景？
管道/FIFO、消息队列、共享内存、信号量、信号、socket 六类。管道/FIFO：简单字节流；消息队列：有边界的结构化消息、可按类型收；共享内存：最快，适合大数据，但要自己同步；信号量：同步互斥，常配共享内存；信号：异步事件通知；socket：本机或跨主机通用。本工程用 SocketCAN 走的就是 socket 这条路。
自评：□ 能讲清　□ 模糊　□ 不会
Q12管道（pipe）和命名管道（FIFO）的区别？
匿名管道只能亲缘进程用，FIFO 有文件名、任意进程可用。pipe 靠 fork 继承 fd，无名字；FIFO 是文件系统里的一个路径，无亲缘关系的进程也能 open 来通信。二者都是半双工字节流。
自评：□ 能讲清　□ 模糊　□ 不会
Q13共享内存为什么最快？为什么必须配信号量？
因为它免去了内核与用户之间的数据拷贝。共享内存把同一块物理内存映射进多个进程的地址空间，读写不经过内核拷贝，所以最快。但内核只提供内存、不提供任何同步，多进程同时读写会乱，必须用信号量/互斥锁保护。
自评：□ 能讲清　□ 模糊　□ 不会
Q14System V IPC 和 POSIX IPC 的区别？
功能对应，接口风格不同。System V：shmget/semget/msgget，用 key 换 id；POSIX：shm_open/mq_open/sem_open，用"名字"（路径风格），更像文件 API，更现代、更推荐。
自评：□ 能讲清　□ 模糊　□ 不会
Q15消息队列和管道（字节流）的区别？
消息队列有"消息边界"和类型，管道没有边界。消息队列按条收发（msgrcv 还能按 type 选择性接收），天然适合结构化消息；管道是纯字节流，发两次可能粘成一次读出来，也没有类型。
自评：□ 能讲清　□ 模糊　□ 不会
Q16信号（signal）和信号量（semaphore）是一回事吗？
不是，一个是"通知"，一个是"同步"。信号是异步事件通知机制（kill 发送、sigaction 注册处理函数，如 SIGINT/SIGTERM）；信号量是同步原语（P/V 操作），用于互斥和计数。名字像，作用完全不同。
自评：□ 能讲清　□ 模糊　□ 不会
Q17要把"RT 线程算出的位姿"给另一个进程，该用什么？
共享内存 + 信号量。位姿需要高频、低延迟读取，共享内存避免了数据拷贝，最快；再用信号量保证读到的是完整的一帧。本工程位姿目前还在同进程内（0x6FFF 数组），若拆成两个进程就该这么做。
自评：□ 能讲清　□ 模糊　□ 不会

§3 网络编程

Q18TCP 三次握手、四次挥手的过程？为什么挥手要四次？
握手三次（SYN / SYN+ACK / ACK），挥手四次（FIN / ACK / FIN / ACK）。握手是为了双方确认收发能力并同步序号。挥手之所以四次，是因为 TCP 全双工——一方说"我没数据发了"，另一方可能还有数据要发，所以"关"要分两个方向各关一次。
自评：□ 能讲清　□ 模糊　□ 不会
Q19为什么必须有 TIME_WAIT？持续多久？
一是保证最后的 ACK 能送达，二是让旧报文消散。若最后那个 ACK 丢了，对方会重发 FIN，必须有端口能响应；同时等旧连接的报文在网络里死光，避免被新连接错收。时长约为 2MSL（报文最大生存期的两倍）。
自评：□ 能讲清　□ 模糊　□ 不会
Q20什么是粘包 / 拆包？怎么解决？
TCP 是字节流、没有消息边界，多次 send 会被合并、一次 send 会被拆开。解决办法：长度前缀（先发 4 字节表示长度，再发内容，最稳）、定长消息、或分隔符（如 \r\n）。本工程 HMI 若把 CiA-309 换成自定义 TCP 协议，就用长度前缀。
自评：□ 能讲清　□ 模糊　□ 不会
Q21TCP 和 UDP 的区别？各自适用场景？
TCP 面向连接、可靠有序；UDP 无连接、不可靠、开销小、延迟低。TCP 适合文件传输、命令下发、HTTP；UDP 适合实时音视频、广播、心跳、能容忍少量丢包的场景。本工程 CAN 上的 PDO 更像"UDP 思路"（周期广播、无应答），SDO 更像"TCP 思路"（点对点、有应答）。
自评：□ 能讲清　□ 模糊　□ 不会
Q22select / poll / epoll 的区别？epoll 好在哪？
epoll 把"遍历"换成"只返回就绪的"，适合大量连接。select 用位图、有 1024 上限、每次调用都要把集合拷进内核并全量轮询 O(n)；poll 用数组去掉了上限但仍是 O(n) 全量轮询；epoll 在内核维护红黑树 + 就绪链表，只返回就绪 fd，接近 O(就绪数)。本工程 CO_epoll_wait 同时等 CAN 和网关，见 [CO_epoll_interface.c](file:///home/zcy/Project/panasonic_canopen_agv/CO_epoll_interface.c)。
自评：□ 能讲清　□ 模糊　□ 不会
Q23epoll 的水平触发（LT）和边缘触发（ET）的区别？
LT 是"还有数据就一直通知"，ET 是"只在状态变化那一刻通知一次"。LT 编程简单、不易丢数据、可用阻塞 fd；ET 必须一次读到 EAGAIN（读空），否则剩余数据不再通知，且必须用非阻塞 fd，效率更高。本工程用默认的 LT。
自评：□ 能讲清　□ 模糊　□ 不会
Q24服务器为什么通常要设 SO_REUSEADDR？
为了快速重启时能立刻重新绑定端口。否则端口处于 TIME_WAIT 期间无法 bind/listen，得等约 2MSL，服务器重启会"地址被占用"。
自评：□ 能讲清　□ 模糊　□ 不会
Q25TCP 三次握手能不能改成两次？
不能，两次无法可靠确认双方收发能力。缺了最后一次 ACK，被动方无法确认"自己的接收能力"和"对方确实收到了我的 SYN+ACK"都正常；还可能因网络里滞留的旧 SYN 建立错误连接。三次是最小可靠次数。
自评：□ 能讲清　□ 模糊　□ 不会

§4 IO 模型与内存

Q26Linux 有哪五种 IO 模型？
阻塞、非阻塞、IO 多路复用、信号驱动、异步 IO。前四种都算同步 IO（真正的"内核→用户"数据拷贝阶段仍要程序自己做），只有异步 IO（AIO）是内核全程代劳、完成才通知。epoll 属于"IO 多路复用"。
自评：□ 能讲清　□ 模糊　□ 不会
Q27"阻塞/非阻塞"和"同步/异步"是一回事吗？
不是。阻塞/非阻塞看"调用是否立即返回"，同步/异步看"数据拷贝谁来做"。阻塞与否由 fd 的 O_NONBLOCK 决定；同步意味着数据从内核拷到用户缓冲还得用户自己 read 触发。所以 epoll 是同步的，AIO 才是异步的。
自评：□ 能讲清　□ 模糊　□ 不会
Q28虚拟内存是什么？为什么需要它？
每个进程一套独立虚拟地址空间，由 MMU 映射到物理内存。好处：进程隔离（互不踩内存）、可运行超过物理内存的程序（换页）、内存保护、共享（共享库 / COW）。这也是"进程比线程重"的根源。
自评：□ 能讲清　□ 模糊　□ 不会
Q29malloc 和 mmap 是什么关系？内存泄漏的本质是什么？
malloc 是用户态分配器，大块内存底层直接用 mmap。小块从堆（brk 扩展）分配，大块（glibc 通常 ≥128KB）直接 mmap 一块匿名内存；free 后大块会 munmap 归还。内存泄漏的本质就是 malloc 之后没有 free，进程存活期间这块内存再也回不去。
自评：□ 能讲清　□ 模糊　□ 不会

§5 工具链与调试

Q30程序出现段错误（Segmentation fault），你怎么定位？
开 core dump，用 gdb 看调用栈。① 编译加 -g；② ulimit -c unlimited 打开 core；③ gdb ./prog core，bt 看栈、frame N 切帧、print 看变量；④ 或直接 gdb run 复现。常见原因：空指针、数组越界、use-after-free、栈溢出。
自评：□ 能讲清　□ 模糊　□ 不会
Q31valgrind 能查什么？怎么用？
查内存泄漏、越界、使用未初始化内存、use-after-free。用法：valgrind --leak-check=full --track-origins=yes ./prog。代价是慢（10~30 倍），适合在测试阶段跑，不适合上线。
自评：□ 能讲清　□ 模糊　□ 不会
Q32strace 是干什么的？什么时候用？
跟踪进程的系统调用和信号，看程序到底在向内核要什么。用法：strace ./prog、strace -p PID、strace -e trace=open,read。排查"卡在哪一步""系统调用返回了什么错误码"最有用——比如本工程真机上 EPOLL 报 EOPNOTSUPP(95) 就靠它发现。
自评：□ 能讲清　□ 模糊　□ 不会
Q33程序从源码到可执行经历了哪几步？
预处理 → 编译 → 汇编 → 链接。cpp 展开宏和头文件，cc1 生成汇编，as 生成目标文件 .o，ld 合并目标文件和库生成可执行。理解这条链能解释大部分报错：编译错误 = 语法/头文件问题，链接错误 = 库或符号找不到。
自评：□ 能讲清　□ 模糊　□ 不会
Q34CMake 相比手写 Makefile 的优势？
跨平台、自动依赖分析、target 语义更清晰。CMake 能生成 Makefile / Ninja / VS 工程，自动分析头文件依赖，大工程几乎都用它；手写规则繁琐易错。本工程现在还是 [Makefile](file:///home/zcy/Project/panasonic_canopen_agv/Makefile)，改 CMake 正好是一次实战。
