第 10 站 · 下行控制（上）：CiA402 状态机与使能时序

本站定位：前九站把「上行」做到了极致——收帧、里程计、Qt 上位机画轨迹，全通了。但整台车目前只会听（读电机的状态与位置），不会说（把指令发回电机）。本站开始补「下行」：给对象字典里本来就有的 0x6040/0x6060/0x607A 接上一条下发路，并按 CiA402 的时序把电机从「未使能」推到「能转」。

为什么值得单独一站：① 这是 AGV 主控的本职——面试必问「你怎么让电机动起来、怎么做使能时序」；② 差速逆解（下一站）最终也要落到本站的 0x607A/0x60FF 上；③ 它把「读过 CANopen」升级为「做过 CANopen 控制」。

阅读顺序：§0 地图 → §1 CiA402 状态机（不看代码）→ §2 词典已就绪 → §3 下行通道怎么建 → §4 使能时序代码 → §5 NMT 主站 → §6 零硬件验证 → §7 小结。

§1 CiA402 状态机：驱动器怎么才算「能转」

1.1 为什么不能「一上来就发目标位置」

伺服/步进驱动器（本工程用的是森创 CANopen 一体机）遵循 CiA402 规范。它把「电机能不能动」抽象成一个状态机：你必须按顺序把控制字 0x6040 的若干位写成特定值，驱动器才一步步从「上电」走到 Operation enabled（可运行）。在此之前，你发多少目标位置它都不理。

这就是为什么很多新手「报文格式全对、电机就是不转」——不是报文错，是没使能。

1.3 两个「字」：控制字与状态字

2.2 默认值其实已经「预设了意图」

看三个默认值，你会发现这套字典的作者本来就打算让它跑下行：

  • 0x6040 = 0x0004：只有 bit2（Quick stop）置 1，表示「没在快停」，但尚未使能——标准的初始控制字。
  • 0x6060 = 3：模式 3 = Profile Velocity（速度模式）。这正是 AGV 差速底盘最常用的模式（给轮速、不用管位置）。
  • 0x1800 的 TPDO 映射 0x1A00 里，默认就映射了 0x6040 + 0x60FF（控制字 + 目标速度，OD.c:148-158）——一条现成的「下行」报文模板。

结论：不缺对象、不缺映射、连模式都替你选好了。缺的只有两件事：一条把 0x6040 真正发出去的通道（§3），和一段按状态字一步步使能的时序（§4）。

2.3 ⚠ 一个必须先填的坑：状态字根本没落地

使能时序每一步都要读状态字（0x6041）来判断下一步发什么。但看 OD.c 里 0x6041 的定义：

.o_6041_statusword = {
    .dataOrig = NULL,                        /* ★ 没有存储！ */
    .attribute = ODA_SDO_R | ODA_TRPDO | ODA_MB,
    .dataLength = 2
},

这意味着什么？dataOrig = NULL 表示这个对象背后没有任何 RAM 变量。RPDO（0x38A）里其实带着状态字（映射项 0x60410010，见 CO_application.c:143），但因为没地方存、又没注册钩子，收帧时
被协议栈直接丢掉。
修法与第 7 站给 0x6064 加钩子完全一样：注册一个 write 钩子，把收到的状态字存进一个全局变量（本站记为 g_sw_r/g_sw_l）。细节见 §4.3。

§3 把「说」的通道建起来

3.1 三条路：TPDO / SDO / NMT

把指令从主站送到驱动器，CANopen 里有三种手段，用途完全不同：

表 10-4 三种下行通道对比
通道机制适合什么代价 / 注意
TPDO预先配好映射，运行时只写 OD，栈按节拍/事件自动发送周期性下达：控制字 + 目标速度/位置要配映射与 COB-ID；受 NMT 状态约束
SDO一问一答，走 0x600/0x580+nodeID偶发配置：改模式、改加速度、写参数握手开销大，不适合每拍；需开 SDO client
NMT只发「命令」（启动/停止/复位），不带数据整机状态切换、故障复位不改数据；是「总开关」不是「油门」（见 §5）

本站走 TPDO——因为控制字和目标速度需要周期性刷新，而 SDO 每拍一问一答太重，NMT 又带不了数据。

3.2 现状：只配了「收」，没配「发」

看 app_programStart()（CO_application.c:107-199），它只做了「接收侧」的配置：给右轮配 RPDO 0x1400→0x38A（:133-152），给左轮配 RPDO 0x1401→0x38B（:168-187）。没有任何一行碰 TPDO（0x1800/0x1A00）。

换句话说：工程今天只会收。要下行，得在这里补上「发送侧」的配置。

3.3 好消息：右轮的 TPDO 默认就已映射好

翻 OD.c 会发现，右轮那本字典（OD）的 TPDO 默认就是可用的：

表 10-5 两条 TPDO 的默认状态（右轮 OD vs 左轮 OD_2nd）
对象默认值 / 含义
OD · 0x1800 通信参数COB_IDUsedByTPDO = 0xC000050A（有效位 + 0x50A）；transmissionType = 0xFE（变化即发）、inhibitTime = 0x10（1.6ms）、eventTimer = 0x0100（256ms 心跳式兜底）。见 OD.c:116-123。
OD · 0x1A00 映射参数已映射 2 项：0x60400010（控制字 2 字节）+ 0x60FF0020（目标速度 4 字节）。见 OD.c:148-158。
OD_2nd · 0x1800 通信参数COB_IDUsedByTPDO = 0xC0000180（有效位 + 0x180）。见 OD_2nd.c:92-98。
OD_2nd · 0x1A00 映射参数空：numberOfMappedApplicationObjectsInPDO = 0x00。左轮要下行，得自己补映射。见 OD_2nd.c:124-131。

左右不对称，注意两点：① 右轮 TPDO 映射是现成的，左轮（OD_2nd）映射是空的，需要在 app_programStart 里补一段（照抄右轮 RPDO 那段的写法即可）；② 两本字典里 0x6040 的属性还不一样——OD 是 ODA_TPDO（可映射进 TPDO，正是下行要的），OD_2nd 是 ODA_RPDO（OD.c:1668 vs OD_2nd.c:1454）。左轮若要走 TPDO，它的属性需一并核对。

3.4 真机必须对齐的一件事：COB-ID

默认 COB-ID 0x50A、0x180 是「字典默认值」，不一定等于真实驱动器愿意接收的地址。TPDO 发出去的对端是驱动器的 RPDO，它的 COB-ID 通常按机型/节点号分配（常见 0x200+nodeID、0x300+nodeID…）。

零硬件阶段先记住结论：COB-ID 与映射必须「主站发什么、驱动器收什么」严格一致。
没有真机时，用 candump 抓一段（见 §6 的仿真从站）就能验证；有真机时，用它自带的 EDS/手册或抓包确定真正的 RPDO 地址，再回来改 0x1800 的 COB-IDUsedByTPDO。这一步不对，后面时序全对也没用——报文发给了空地址。

§4 使能时序：把状态机写进 RT 拍

4.1 用一个枚举表示状态

§1 的状态机落地成代码，就是一个「读状态字 → 决定控制字 → 写回去」的循环。因为它要跟着实时节拍走，所以放在 app_programRt（CO_application.c，第 7 站里程计所在的同一钩子）里，紧跟在 if (!timerEvent) return; 之后。

4.2 骨架代码

下面是一个电机的一步推进。左右轮各调一次，分别用各自的字典。

/* ===== 第 10 站新增：CiA402 使能时序（放 app_programRt，真节拍内） ===== */

/* 一个电机的状态推进。st: 0=未使能 1=就绪 2=已接通 3=已使能 */
static void cia402_step(uint16_t sw, uint16_t *cw, int *st)
{
    if (sw & 0x0008) {              /* bit3：故障 */
        *cw = 0x0080;               /* Fault reset（bit7 上升沿清故障） */
        *st = 0;                    /* 回到起点，重新走一遍 */
        return;
    }
    switch (*st) {
    case 0:                         /* 未使能 */
        *cw = 0x0006;               /* Shutdown */
        if ((sw & 0x7F) == 0x0021)  /* Ready to switch on ？ */
            *st = 1;
        break;
    case 1:                         /* 已就绪 */
        *cw = 0x0007;               /* Switch on */
        if ((sw & 0x7F) == 0x0023)  /* Switched on ？ */
            *st = 2;
        break;
    case 2:                         /* 已接通 */
        *cw = 0x000F;               /* Enable operation */
        if (sw & 0x0004)            /* Operation enabled ★ 能转了 */
            *st = 3;
        break;
    case 3:                         /* 已使能：可以开始下目标了 */
        *cw = 0x000F;               /* 保持使能 */
        break;
    }
}

/* —— 在真节拍里调用（左右各一次）—— */
static int stR = 0, stL = 0;
uint16_t   cwR, cwL;
cia402_step(g_sw_r, &cwR, &stR);        /* 右轮：状态字来自 §4.3 的钩子 */
cia402_step(g_sw_l, &cwL, &stL);        /* 左轮 */

OD_RAM.x6040_controlword     = cwR;     /* 写右轮控制字 → 触发 TPDO 下行 */
OD_2nd_RAM.x6040_controlword = cwL;     /* 写左轮控制字 */

为什么「只写 OD 就行」？因为 §3.3 已经把 0x6040 映射进了 TPDO（transmissionType = 0xFE = 变化即发）。你改 OD_RAM.x6040_controlword，协议栈在下一拍 CO_TPDO_process() 里发现值变了，就自动把这帧发出去。你只管写字典，发送交给栈——这就是 TPDO 相对 SDO 的省心之处。

4.3 前置条件：先能读到状态字

上面代码里的 g_sw_r/g_sw_l 不是凭空来的——它们正是 2.3 里那个坑的补法。状态字本来就在 RPDO 里送上来了（映射 0x60410010），只是被丢了。补一个钩子把它接住：

/* 与第 7 站 H6064_write 完全同构：只存值，不计算 */
static uint16_t g_sw_r, g_sw_l;

ODR_t H6041_write(OD_stream_t *stream, const void *buf,
                  OD_size_t count, OD_size_t *countWritten)
{
    if (stream == NULL || stream->object == NULL || buf == NULL)
        return ODR_DEV_INCOMPAT;
    uint16_t *can_id = (uint16_t*)stream->object;   /* 0x038A 右 / 0x038B 左 */
    uint16_t  sw     = *(uint16_t*)buf;

    if      (*can_id == 0x038A) g_sw_r = sw;
    else if (*can_id == 0x038B) g_sw_l = sw;
    else return ODR_DEV_INCOMPAT;

    *countWritten = count;
    return ODR_OK;
}

顺序很重要：先接住状态字，再写时序。否则 g_sw_r 恒为 0，状态机永远停在 case 0，你会看到控制字一直在 0x0006 打转、电机毫无反应——而报文看起来「全对」。这正是本站想让你避开的最典型坑。

4.4 左右两台：OD 与 OD_2nd

本工程用的是「每轮一本字典」的结构：右轮走 OD（OD_RAM），左轮走 OD_2nd（OD_2nd_RAM），与 app_programStart 里 RPDO 左右分开的写法（0x38A/0x38B）一一对应。所以：

  • 右轮：OD_RAM.x6040_controlword / OD_RAM.x60FF_targetVelocity；
  • 左轮：OD_2nd_RAM.x6040_controlword / OD_2nd_RAM.x60FF_targetVelocity。

两轮的使能状态（stR/stL）各自独立推进——万一左轮报故障，右轮不该被拖下水。

§5 NMT 主站：把驱动器「叫醒」的总开关

5.1 为什么除了时序，还要 NMT

要让一个 CANopen 从站会发 TPDO，它必须先处于 Operational 状态——这是 NMT（网络管理）说了算的，和 CiA402 是两层：

  • NMT：管「整台设备开不开机」。切状态不带数据，是全网络的广播式总开关。
  • CiA402：管「电机使不使能」。在你已进 Operational 的前提下，用控制字一步步把电机推到能转（§1/§4）。

本项目的现状：AGV 一直在收 0x38A/0x38B，说明两个驱动器本来就已在 Operational（多半上电自启动）。所以「NMT 启动」在本项目不是每拍必需；但作为主站，你必须掌握它——驱动器掉线重连、故障复位、或改用不自启动的机型时，都要靠它。

5.2 只需一个 API：CO_NMT_sendCommand()

好消息是，工程编译时已经把 NMT 主站能力打开了：

5.3 联调顺序（照这个顺序走，不会乱）

① 总线就绪vcan 起好、candump 开着，确认能看到 0x38A/0x38B 在滚。
② NMT 启动发 CO_NMT_ENTER_OPERATIONAL（若驱动器已自启动，跳过也见得到 TPDO）。
③ 接住状态字确认 g_sw_r/g_sw_l 有值（§4.3 的钩子生效）。这是后面所有的前提。
④ 跑使能时序看 0x6040 阶梯上升：0x0006 → 0x0007 → 0x000F；状态字同步 0x0021 → 0x0023 → 0x0027。
⑤ 下目标写 0x60FF（速度模式）或 0x607A（位置模式），看 0x6064 开始变化。

§6 零硬件验证：把「哑」从站改成「会回话」的从站

6.1 现状：仿真从站只会「自言自语」

第 7 站用的 tools/sim_motors.py 是一个单向从站：它以 10 Hz 广播固定的状态字 0x0237（声称「已使能」）和一条位置曲线（sim_motors.py:54, 79-81）。它不看主站发了什么。

对上行（收位置）够用；但验证下行不行——因为它不会响应控制字，你没法确认「我发的 0x6040 到底到没到、驱动器状态有没有跟着变」。

6.2 改造思路：让从站「听得见、答得上」

做一个反向增强版从站，补三件事：① 收主站下行帧（0x50A/0x180），② 用迷你 CiA402 状态机根据收到的控制字算出状态字，③ 把状态字连同位置回发 0x38A/0x38B。这样整条闭环在 vcan 上就活了。

"""tools/sim_motors_downlink.py —— 会回话的仿真从站（骨架）"""
import socket, struct, sys, time

iface = sys.argv[1] if len(sys.argv) > 1 else "vcan0"
s = socket.socket(socket.AF_CAN, socket.SOCK_RAW, socket.CAN_RAW)
s.bind((iface,)); s.settimeout(0.01)

def step(st, c):
    """迷你 CiA402：输入(当前状态字,控制字)，返回下一状态字。够验证即可。"""
    if c & 0x0080:              return 0x0040   # Fault reset → Switch on disabled
    if (c & 0x0006) != 0x0006:  return 0x0040   # 电压未使能
    if not (c & 0x0008):
        return 0x0023 if (c & 0x0001) else 0x0021   # Switched on / Ready
    return 0x0027                                # Operation enabled ★

sw  = {"R": 0x0040, "L": 0x0040}   # 初始：Switch on disabled
cw  = {"R": 0x0000, "L": 0x0000}
vel = {"R": 0, "L": 0}; pos = {"R": 0, "L": 0}
DOWN = {0x50A: "R", 0x180: "L"}    # 主站下行 COB-ID（用你实际配的 0x1800 COB-ID）

while True:
    try:                                    # ① 收下行：0x6040 + 0x60FF
        f = s.recv(16); cid, dlc = struct.unpack("=IB3x", f[:8]); d = f[8:8+dlc]
        who = DOWN.get(cid)
        if who and dlc >= 6:
            cw[who]  = struct.unpack("<H", d[0:2])[0]
            vel[who] = struct.unpack("<i", d[2:6])[0]
    except socket.timeout:
        pass
    for who in ("R", "L"):                  # ② 跑状态机 + 按轮速积分位置
        sw[who] = step(sw[who], cw[who])
        if sw[who] & 0x0004:
            pos[who] += int(vel[who] * 0.01)    # 10 ms 一拍
    s.send(struct.pack("=IB3x8s", 0x38A, 6, struct.pack("<Hi", sw["R"], pos["R"])))  # ③ 回发
    s.send(struct.pack("=IB3x8s", 0x38B, 6, struct.pack("<Hi", sw["L"], pos["L"])))
    time.sleep(0.01)

站在主站角度，这就等价于「接了一台会听控制字的电机」：你写 0x6040，它的状态字就跟着爬；到了 0x0027 你再给 0x60FF，位置才开始动。零硬件复现了 §5.3 的完整时序。
