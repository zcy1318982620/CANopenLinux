1. 一页地图：CANopen 就四样东西

忘掉细节，先记住这张图。CANopen 这个协议，掰开揉碎就四样东西：一条总线（大家共用、广播）、一张对象字典 OD（设备所有变量都住这张表）、一组服务（SDO / PDO / NMT / SYNC / EMCY / 心跳）、一个状态机（INIT→PRE-OP→OP→STOPPED）。本工程就是把「左右电机驱动器」通过这张共享字典，接到同一个从站进程里。

一句话记忆：CANopen = 「用一条 CAN 总线，去读写一张叫做 OD 的表；读写的规矩，分成 SDO 和 PDO 两扇门」。NMT 决定这扇门开不开，SYNC 决定什么时候推，EMCY / 心跳负责出事了报一声。
简历话术：「熟悉 CANopen 应用层协议，理解对象字典、SDO/PDO 通信、PDO 映射与 NMT 状态机，能基于 CANopenNode 从站完成 CiA402 驱动的接入与实时数据回传。」

2.3　值是怎么进 OD 的：两条来源，一个出口

谁把值写进 OD？
   ┌── SDO（主站慢慢问，带 index:subindex）──┐
   │                                          ├──▶ OD 表项 (index:subindex)
   └── PDO（主站快快推，不带地址、靠映射）──┘            │
                                                        ├─ 普通表项：直接落 RAM 变量
                                                        └─ 挂过钩子：转调 .write()
                                                               └─ 本工程 0x6064 ─▶ H6064_write()

线程分工：SDO/网关在主线程；PDO 在 rt 线程。两边都写同一张 OD_RAM，故用 CO_LOCK_OD 保护。

3. 两扇门：SDO 与 PDO

OD 是仓库，进出仓库只有两扇门。把这两扇门的差别想明白，CANopen 就理解了一大半。

表 3-1　SDO vs PDO
维度SDO（服务数据对象）PDO（过程数据对象）
带不带地址带：每帧都写明 index:subindex，想去哪去哪。不带：地址是「预先配好」的映射（0x1600），每帧按固定布局装数据。
要不要握手要：一问一答（请求帧 + 响应帧），可靠但慢。不要：主站单方向推，从站收到即用，快了不保证。
长度任意长度（可分块传大文件）。≤ 8 字节（一帧 CAN 的上限），固定布局。
COB-ID0x600+node(收) / 0x580+node(发)。映射里指定，如本项目 0x38A/0x38B。
典型用途配置参数、读诊断、升级固件、读里程计 0x6FFF。周期性实时数据：状态字、位置、速度。
本工程Qt 上位机用 SDO 读 0x6FFF 里的 x/y/θ。主站用 0x38A/0x38B 把两轮位置推进来。
 
两扇门的心智图

  SDO（带地址、要握手、慢但稳）          PDO（不带地址、不握手、快）
  ┌──────────────────────────┐         ┌──────────────────────────┐
  │ 请求: write 0x6064 = 1000 │         │ 帧 0x38A: [6041][6064]    │
  │         ▲                 │         │            ▲             │
  │         └── 响应: OK      │         │     布局写死在 0x1600 映射 │
  └──────────────────────────┘         └──────────────────────────┘
       想去哪去哪、可读可写              只能在配好的映射里、单向推
一句话面试答法：「SDO 像快递寄件——每次填地址单、有签收，慢但准；PDO 像传送带——事先排好货位，东西一放就走，快但只走固定路线。我项目里实时数据（状态字、位置）走 PDO，配置和里程计回读走 SDO。」

4. PDO 映射：8 字节里怎么塞、DLC 怎么算

PDO 帧不带地址，那从站怎么知道「收到的 6 个字节哪几个是状态字、哪几个是位置」？答案：靠事先写好的映射（OD 里的 0x1600/0x1601）。映射表里每一个数，都编码了「取哪个变量、占几个 bit」。

4.1　一个映射值 = 索引 + 子索引 + 位长

CANopenNode 解析映射值的代码在 [CO_PDO.c:93-96](file:///home/zcy/Project/panasonic_canopen_agv/CANopenNode/301/CO_PDO.c#L93-L96)，就四行，值得背下来：

文件：CANopenNode/301/CO_PDO.c

:94    uint8_t  subIndex         = (uint8_t)(map >> 8);      /* 次8位  = 子索引 */
:95    uint8_t  mappedLengthBits = (uint8_t) map;            /* 低8位  = 位长(bit) */

于是本工程 startup 里写的两个映射值（[CO_application.c:132](file:///home/zcy/Project/panasonic_canopen_agv/CO_application.c#L132)、[:137](file:///home/zcy/Project/panasonic_canopen_agv/CO_application.c#L137)）就能逐位拆开：

表 4-1　右电机 RPDO1（0x1600）两个映射值的含义
映射值拆解含义
0x60410010index=0x6041 / sub=0x00 / bits=0x10取 0x6041 状态字，占 16 bit = 2 字节。

4.2　0x38A 这一帧的字节布局

帧 COB-ID = 0x38A（右电机），DLC = 6，方向：主站 ──▶ 本从站

  字节:  B0     B1      B2     B3     B4     B5
        ┌──────┬──────┬──────┬──────┬──────┬──────┐
        │     0x6041 状态字  │       0x6064 实际位置     │
        │      (16 bit, 小端)  │       (32 bit, 小端)      │
        └──────┴──────┴──────┴──────┴──────┴──────┘
          第 1 条映射(2B)      第 2 条映射(4B)
          0x60410010           0x60640020

  例：位置 = 1000 (0x000003E8) → 小端字节序写进来是  E8 03 00 00
      状态字 = 0x0237          → 小端字节序写进来是  37 02

所以「PDO 快」不是玄学：地址不用每次传，布局写死在映射里，收到 6 个字节直接按位置切开、按小端数值还原，然后写进 OD。

简历话术：「我能根据 0x1600 映射值手算 PDO 的 payload 布局和 DLC：比如 0x60410010 + 0x60640020 = 2+4 = 6 字节，帧里前 2 字节是状态字、后 4 字节是位置，多字节按小端还原。」
