第 7 站 · 里程计：差速运动学 → 位姿 x, y, θ

本站定位：阶段 B「做出增量」的收官。第 6 站我们已经能在 RT 线程里 1ms 一拍拿到左右轮的真实位置（posR / posL，原始计数），但它们只是两个孤立的数字。本站把这两个数字，变成「车在哪」——位姿 x, y, θ。

一句话概括：在同一批钩子里，把「两个轮子转了多少」按差速运动学积分成「车走了多远、转了多少、在哪」。

为什么值得单独一站：① 这是从站节点第一次输出「有物理意义的量」，是后面 Qt 上位机（第 8 站）要显示的东西；② 它复用第 6 站已经搭好的 RT 节拍与钩子，不新增线程、不新增总线报文——是「在已有链路上加一节」的典型范例。

阅读顺序：§1 讲物理模型（不看代码）→ §2 讲数据从哪来、在哪算（看链路）→ §3 讲要量的参数 → §4 才是动手写 → §5/§6 衔接与自测。

§1 差速运动学：三个公式把轮子变成车

1.1 双轮差速模型在讲什么

这台 AGV 是双轮差速：左右各一个驱动轮，分别由两个电机独立驱动（对应我们工程里的 OD／右电机 与 OD_2nd／左电机）。它没有转向轮——转弯靠左右轮速度不同。俯视看是这样的：

                前进方向 (θ=0，车头朝 +x)
                          ▲
                          │
        ┌─────────────────┼─────────────────┐
        │                 │                 │
        │              车体中心             │
        │                 ●                 │
        │                 │◄──── b ────►│    │   b = 两轮中心距（轮距）
        │                 │                 │
       ─●─────────────────┼─────────────────●─
       左轮 L            车体中轴           右轮 R
      (OD_2nd)                            (OD)
  • 左轮（OD_2nd / RPDO 0x38B）：累计位置 posL。
  • 右轮（OD / RPDO 0x38A）：累计位置 posR。
  • 车体的姿态用三个量描述：x, y（车体中心在世界坐标里的位置，单位 m）和 θ（车头朝向角，单位 rad）。

1.2 三步公式（本站的全部数学）

任意一拍（1ms），我们从两个轮子的累计位置里取「这一拍各自转了多少」（记为 ΔposR、ΔposL，单位是驱动器给的计数），然后：

表 7-1 差速运动学三步
步骤公式这一步在干什么
① 计数 → 轮面位移dR = k · ΔposR
dL = k · ΔposL		把「编码器计数」换算成「轮子边缘实际滚过的米数」。k 是每计数对应的米数（见 §3 标定）。
② 两轮 → 车体d = (dR + dL) / 2
dθ = (dR − dL) / b		两个轮子的平均就是车体前进了多少 d；两个轮子的差除以轮距就是车体转了多少 dθ。等速前进→差=0→θ 不变；一轮快一轮慢→转小弯；同速反向→原地转。
③ 累加成位姿x += d · cos(θmid)
y += d · sin(θmid)
θ += dθ		把这一步的位移按当前朝向投影到世界坐标的 x / y 上，并更新朝向。θmid 见 1.3。

1.3 用欧拉法还是中点法

第 ③ 步有个细节：这一步的位移 d，应该沿着「转之前的方向」投影，还是「转之后的方向」，还是「转一半时的方向」？三者分别是欧拉法、后向法、中点法。

  欧拉法(转之前θ)        中点法(转一半 θmid = θ+dθ/2)      后向法(转之后θ+dθ)
        ╲                     ╲                              ╲
         ╲ 本次 d              ╲ 本次 d                       ╲ 本次 d
          ╲                     ╱╲  ← 取中间朝向               ╲
           ╲                   ╱  ╲                             ╲
   误差偏大(总是偏内/外)      误差最小(正负抵消)            误差偏大

我们的采样节拍是 1ms、车速又低，单拍转角 dθ 极小，用中点法几乎零成本、精度最好，所以选它：

  θmid = θ + dθ / 2
  x += d * cos(θmid)
  y += d * sin(θmid)
  θ += dθ

注意书写顺序：θmid 必须用「更新前的 θ」算，θ 最后才累加。x/y 也必须在 θ 更新前用 θmid 算完。顺序错了，公式就退化成别的积分法。

§2 数据从哪来、在哪算：只碰两个已有钩子

所有公式都要有输入。输入是左右轮的位置，输出是位姿。整条链路里，本站只碰两个钩子：一个是收帧钩子（拿数据），一个是RT 拍钩子（算数据）。先把这两个函数讲清楚——它们分别是谁、被谁调、干什么。

2.1 收帧钩子：H6064_write

表 7-3 H6064_write 速查
位置CO_application.c:38（本站要改这里）
干什么两个电机的 RPDO 帧里都有 0x6064（实际位置）。这个函数就是「0x6064 被写时的钩子」：谁往 0x6064 写，它就被叫一次。当前实现只是把位置 printf 出来。

为什么左、右两个扩展共用一个函数？因为 H6064_write 靠 stream->object 这个标记来区分左右。右轮扩展在注册时把 object 指向 objR（值 0x038A，CO_application.c:119-121），左轮指向 objL（0x038B，CO_application.c:149-151）。函数体里一句 if (*can_id == 0x038A) ... else if (*can_id == 0x038B) ... 就分开了。

2.3 关键结论：两个钩子在同一线程，不用加锁

这是本站最容易踩坑、也最值得写进面试答案的一点。看一眼 RT 循环的执行顺序：

rt_thread() 每一圈的固定顺序                    (CO_main_basic.c:885-910)

  CO_epoll_wait(&epRT)            ← 等定时器/报文/门铃
        │
        ▼
  CO_epoll_processRT(&epRT, CO, true)          (CO_epoll_interface.c:323)
        │  ├─ CO_CANrxFromEpoll()               ← 收 CAN 帧          (:333)
        │  ├─ CO_process_SYNC()                 ← 处理同步帧         (:346)
        │  ├─ CO_process_RPDO()  ──► H6064_write()  ★ 存 posR/posL  (:350)
        │  └─ CO_process_TPDO()                                      (:354)
        ▼
  CO_epoll_processLast(&epRT)
        ▼
  app_programRt(CO, epRT.timerLate_us, epRT.timerEvent)  ★ 算位姿  (CO_main_basic.c:904)
        │
        └──► 回到循环开头

看清楚：存数据的 H6064_write 和算数据的 app_programRt，都在同一个 RT 线程里，而且是同一圈里一前一后顺序执行。既然不存在两个线程同时访问，那么它们共享的变量（比如 odom_posR_raw / odom_posL_raw / odom_new）就不需要加锁。

但要注意边界：一旦这些变量要被主线程/Qt 上位机读（第 8 站），跨线程访问就成立了，那时读侧必须用 CO_LOCK_OD() / CO_UNLOCK_OD() 保护（或在 OD 里以变量形式暴露）。本站内部「存—算」闭环不跨线程，先不加锁是对的。

2.4 为什么必须用钩子，不能直接读对象字典里的 0x6064

一个自然的疑问：既然 RPDO 会把位置写进对象字典，那我在 app_programRt 里直接读 0x6064 的值不就行了？

不行。原因就在现有 H6064_write 的实现里：它没有调用 OD_writeOriginal()（CANopenNode/301/CO_ODinterface.c:75，真正落存储的函数），也没有设置 *countWritten。也就是说，这个钩子把值「接住、打印、丢掉」，值根本没有写回对象字典的真实存储——对象字典里 0x6064 永远停在初值。

这也正好说明：钩子是唯一能拿到实时位置的入口。所以本站的做法就是——既然钩子每次都拿到最新的 posR/posL，那就在钩子里顺手把它存进我们自己的全局变量，供 app_programRt 使用。

顺带一个冷知识：CO_RPDO_process 在 CO_PDO.c:863 调用 OD_IO->write(..., &countWritten) 时不检查返回值、也不校验 countWritten，所以原代码「不设 countWritten」也能照常跑。标准做法（见 CO_PDO.c:44-50 的 OD_write_dummy 示例）是应把 *countWritten = count 回填，本站顺手补上更规范。

§3 标定参数：把「计数」变成「米」

公式里有两个必须实测/查手册的参数：k 和 b。它们决定了里程计的绝对准确度。

表 7-5 标定参数
参数怎么得到代入处
轮半径 r（m）查轮子规格或卷尺量直径除以 2。换算 k
每圈计数 N（counts/rev）查驱动器手册（例：BLVD-KRD 的编码器分辨率）。换算 k
每计数位移 k = 2πr / N（m/count）上两项算出来。① 步：dR = k·ΔposR
轮距 b（m）卷尺量左右轮中心之间的横向距离（不是外缘间距）。② 步：dθ = (dR−dL)/b
左右轮方向 DIR_R / DIR_L实车标定：手动让车沿 +x 直推一段，看 posR/posL 是增还是减；若与预期相反就取 −1。取 Δ 时乘上，统一「前进为正」

方向与符号的验证方法（必做一次）

  1. 把车原地向前推 1 米（直推，不转）。
  2. 观察终端：posR 和 posL 应该都增大，且增大的计数接近 1.0 / k。若某个在减小，就把对应的 DIR 取 −1。
  3. 把车原地左转（右轮前进、左轮后退）。θ 应该增大（逆时针为正）。若变小，说明左右轮接反了，交换两个 DIR。
别忘了链接数学库：本站公式要用 cos()/sin()，需要 #include <math.h>，并且 Makefile 的 LDFLAGS 里要补 -lm。当前 Makefile:64-66 只有 -g -ggdb 和 -pthread，没有 -lm，不加会链接报 undefined reference to 'cos'。

4.3 收帧钩子：从「打印」改成「存」

改后的 H6064_write（CO_application.c:38）。它只做一件事：把最新位置存起来、置旗子。它不计算——因为计算要等 1ms 节拍统一做（万一 1ms 内来两帧，直接算会重复积分）。

ODR_t H6064_write(OD_stream_t *stream, const void *buf,
                  OD_size_t count, OD_size_t *countWritten)
{
    if (stream == NULL || stream->object == NULL || buf == NULL
        || countWritten == NULL) {
        return ODR_DEV_INCOMPAT;
    }
    uint16_t *can_id = (uint16_t*)stream->object;   /* 标记：0x038A / 0x038B */
    int32_t   pos    = *(int32_t*)buf;              /* 已解析好的位置值 */

    if (*can_id == 0x038A)      odom_posR_raw = pos;   /* 右轮 */
    else if (*can_id == 0x038B) odom_posL_raw = pos;   /* 左轮 */
    else return ODR_DEV_INCOMPAT;

    odom_new = true;                 /* 告诉 RT 拍钩子：有新数据了 */
    *countWritten = count;           /* 规范：回填写入字节数（见 §2.4） */
    return ODR_OK;
}

4.4 RT 拍钩子：这里才是积分的地方

改后的 app_programRt（CO_application.c:184）。注意位置——代码要加在「if (!timerEvent) return;」之后，保证只在真节拍上积分一次。

void app_programRt(CO_t *co, uint32_t timerLate_us, bool_t timerEvent)
{
    (void) co;
    /* ……第 6 站的抖动统计代码保持不动…… */
    if (!timerEvent) return;                 /* 非真节拍：不积分 */

    /* ===== 以下为第 7 站新增：里程计积分 ===== */
    static int32_t prevR, prevL;             /* 上拍累计位置(计数) */
    static bool_t  odom_init;                /* 首拍只记录起点，不积分 */

    if (!odom_new) return;                   /* 本拍没收到新位置，跳过 */
    odom_new = false;

    if (!odom_init) {                        /* 首次：把起点记为 0 */
        prevR = odom_posR_raw;
        prevL = odom_posL_raw;
        odom_init = true;
        odom_x = odom_y = odom_th = 0.0;
        return;
    }

    /* ① 取两轮「这拍转了多少计数」，无符号相减处理回绕(§4.5) */
    int32_t dCntR = (int32_t)((uint32_t)odom_posR_raw - (uint32_t)prevR);
    int32_t dCntL = (int32_t)((uint32_t)odom_posL_raw - (uint32_t)prevL);
    prevR = odom_posR_raw;
    prevL = odom_posL_raw;

    /* ① 计数 → 轮面位移(m)，并统一方向 */
    double dR = ODOM_DIR_R * ODOM_K_PER_COUNT * (double)dCntR;
    double dL = ODOM_DIR_L * ODOM_K_PER_COUNT * (double)dCntL;

    /* ② 两轮 → 车体位移/转角 */
    double d  = (dR + dL) / 2.0;
    double dth = (dR - dL) / ODOM_WHEEL_BASE_M;

    /* ③ 中点法累加位姿 */
    double thmid = odom_th + dth / 2.0;
    odom_x += d * cos(thmid);
    odom_y += d * sin(thmid);
    odom_th += dth;

    /* 每秒打印一次（1000 拍 ≈ 1s），别每拍都打 */
    static uint32_t odom_n;
    if (++odom_n >= 1000) {
        odom_n = 0;
        printf("[ODOM] x=%.3f y=%.3f th=%.1fdeg\n",
               odom_x, odom_y, odom_th * 180.0 / ODOM_PI);
        fflush(stdout);
    }
}

4.5 为什么要用无符号相减：位置回绕

驱动器的累计位置是 32 位、会一直往一个方向涨，绕一圈后从最大翻到最小（回绕）。如果直接做有符号减法 posR - prevR，在回绕点会得到一个巨大的错值。

解决办法很简单：两个 uint32_t 相减，结果再当 int32_t 解释。在模 2³² 意义下，只要这一拍真实增量远小于半圈，就永远得到正确的小增量：

  int32_t dCntR = (int32_t)((uint32_t)odom_posR_raw - (uint32_t)prevR);
                        └──────── 先按无符号减（自动模 2^32）────────┘
                └──── 再当有符号读：结果即为这一拍的带符号增量 ────┘

§5 从「能算」到「给上位机」：衔接第 8 站

本站做完，位姿 x,y,θ 已经在 app_programRt 里被算出来了，但它还只是本进程里的几个变量，上位机看不到。第 8 站（Qt 上位机）要拿到它，有两条常见路：

表 7-8 位姿暴露的两条路
方式怎么做代价/适用
① 加进对象字典（SDO 读）在 OD 里新增一个厂商段条目（如 0x2xxx），把 odom_x/y/th 写进去，上位机用 SDO 周期读。实现简单；SDO 请求是偶发的，实时性一般。适合「看一眼」。
② 用 TPDO 主动上报配置一个 TPDO 映射这几项，由同步帧（本站 0x1006=100ms 已在发 0x080）触发，周期性广播位姿。周期确定、延迟低；要改 OD 与 TPDO 映射。适合「持续跟随」。

跨线程提醒：无论走哪条路，位姿变量都会被「RT 线程写、主线程/发送侧读」。这时就要按 §2.3 的边界规则，用 CO_LOCK_OD()/CO_UNLOCK_OD() 保护读写（或让 OD 以「变量」形式统一访问）。本站内部闭环不跨线程，先不加锁是正确的；第 8 站才是真正引入锁的地方。

6.2 应能回答的问题

  1. 为什么本站不需要加锁？—— 因为存（H6064_write）与算（app_programRt）在同一 RT 线程、同一圈内顺序执行；跨线程才需要锁。
  2. 为什么只能用钩子拿位置、不能读 OD 的 0x6064？—— 因为现有 H6064_write 没有 OD_writeOriginal()、没设 countWritten，值没落进 OD 真实存储。
  3. 为什么积分要放在 timerEvent==true 且加 odom_new 门控？—— 前者保证 1ms 真节拍积分一次、不被报文/门铃唤醒重复触发；后者保证 1ms 内来多帧也只积分一次。
  4. 计数 → 米的换算链路？—— k = 2πr/N，dR = k·ΔposR。
  5. 为什么用中点法、为什么 θmid 要用更新前的 θ、θ 最后才加？—— 见 §1.3、§1.3 的 note。
  6. 位置回绕怎么处理？—— (int32_t)((uint32_t)cur - (uint32_t)prev)。
  7. 改完为什么 Makefile 要加 -lm？—— 用了 cos/sin，缺数学库会链接失败。
