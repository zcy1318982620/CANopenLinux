AGV 主控数据流大图：cmd_vel → 逆解 → 使能/下发 → 里程计回读

这份文档解决什么：代码已经全在仓库里（S7 里程计 / S10 下行 CiA402 / S11 逆运动学），缺的不是功能，而是「能画一张图、能脱稿讲」。本册把整条主控数据流压成一张大图 + 一份函数级走读表，用于面试白板/口述。

一句话讲完这个项目：本工程是一个 CANopen 主控——上位机给一条 cmd_vel(v,ω)，我用差速逆解把它变成左右轮目标转速下发到驱动器（并保证「没使能不动、失联停车、掉线停车」），再从驱动器回读的实际位置用里程计正解积出车体位姿，回传给上位机画轨迹。

素材来源：本册是 docs/AGV_CANOPEN_LEARNING_MAP_S7_ODOMETRY_print.html / ..._S10_DOWNLINK_CIA402_print.html / ..._S11_INVERSE_KINEMATICS_print.html 的汇总视图；细节回到那三册。

行号基线：2026-10-09 工作区（CO_application.c 609 行；逆解/正解已抽到 agv_kinematics.c/h）。若之后改动代码，请以源码为准。

§1 一页大图（先看图，再看字）

图的读法：横向 = 数据在谁手里；箭头 = 谁把数据交给谁。上面两行是「下行（说）」，第三行是「上行（听）」，第四行是「使能环」。节点编号 ①~⑱ 在下文走读表里一一对应。红色框 = 容错点。

一眼看懂的三句话：① 下行是「一条数值走到底」——(v,ω) 只在 ⑥ 被换算一次，之后一路是 counts/s；② 上行是「一条计数走到底」——0x6064 原始计数只在 ⑭ 被积分一次，之后一路是 x,y,θ；③ ⑦ 和 ⑰⑱ 是「控制」，它们让「说」和「听」闭环。

为什么「存」与「算」分两处：收帧钩子跑在 CAN 接收路径上（可能一次处理多帧、也可能被门铃提前唤醒），而积分必须每 1 ms 恰好一次。所以钩子只置旗（odom_new），RT 真节拍见到旗才积分一次（:548-558）。两者同处 RT 线程、同圈先后执行，故共享变量无需加锁。

§5 两个容错点（面试最想问的两句）

5.1 容错点①：安全门限（三合一清零）

代码 CO_application.c:530-534。三个条件任一成立就把两轮目标转速清零：

表 5-1 三个门限条件
条件判据为什么需要
未使能不动(dl_swR & 0x6F)!=0x27 || (dl_swL & 0x6F)!=0x27驱动器没在 Operation enabled 就发速度，指令无意义甚至危险；两轮都要判，一轮没使能就整体不动。
失联停车
(deadman)		cmd_age > CMD_TIMEOUT_TICKS(500)，≈500 ms上位机崩了/网断了，不能带着上次的速度一直跑。由写动作打时间戳，不能由「值变化」判断。
掉线停车CO_HBconsumer_getState(idx0/idx1) == TIMEOUT从站掉线后位置/状态都不再更新，里程计会漂、轮速也没人执行。

5.2 容错点②：心跳容错（HBconsumer 落地）

  • 配置：0x1016 8 槽中用 2 槽——sub0=0x08、sub1=0x000A03E8(node10 右，超时 1000 ms)、sub2=0x000B03E8(node11 左)，其余 0 禁用。见 OD.c:31-35。
  • 读状态：RT 拍 :519-528 用 CO_HBconsumer_getState()，idx 是 0 基数组下标（槽 1→idx0、槽 2→idx1）。
  • 谁报 EMCY：库自动上报 0x8130(CO_EMC_HEARTBEAT)，应用层不用手写；恢复时库自动 CO_errorReset。应用层只做「运动降级 + 跃迁打一行日志」。
  • 一个必知边界：CO_HBconsumer_process() 只在 ACTIVE 时判超时，而 ACTIVE 只在收到过至少一次心跳后才置位 → 从未上线的从站（UNKNOWN）不会报超时。本工程用 dl_sw 门限互补覆盖「上电即没响应」。
编译陷阱：不要在任何地方再加 -DCO_CONFIG_HB_CONS=0。它会整体覆盖 CO_driver_target.h:74-81 的 #ifndef，从而静默禁用 HBconsumer，心跳监控整条失效（QUERY_FUNCT 也一样被吞掉）。

§6 关键设计问答（面试官会追问的 4 个「为什么」）

表 6-1 设计决策与理由
问题回答（一句话 + 证据）
为什么下行用 TPDO 而不是 RPDO？视角问题：PDO 的方向是按本节点定义的。本节点是「主控」，把 0x6040/0x60FF 发出去，对自身而言就是 TPDO（0x1800 的 COB-ID 配成 0x50A/0x50B）。收上来的 0x6041/0x6064 才是 RPDO（0x1400→0x38A）。见 :331-367。
为什么写钩子不自己加锁？SDO 服务端已在外层持有 CO_LOCK_OD（CO_SDOserver.c:555-558），钩子再加锁会死锁。这是 H7000_write/H6064_write/H6041_write 只做「存值」的根本原因。
为什么 RT 拍要 CO_LOCK_OD？因为有跨线程访问：OD_RAM 的写侧在 rt_thread，而 CiA-309 网关的读侧在 main 线程。:537-546、:577-581 的锁是为「别人也在读同一个 OD」而加，不是为了防自己。
为什么循环里用「即使非节拍也 return」？epoll_wait 的唤醒有三类：定时器到点（真节拍）、跨线程门铃、CAN 到达。只有第一类才代表 1 ms 栅格，积分/抖动统计都必须在真节拍段（:453-456），否则 1 ms 内会被重复触发。
