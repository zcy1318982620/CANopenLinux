工程：panasonic_canopen_agv ｜ 主题：统一日志分级 · 所有系统调用返回值判错

§1 为什么要做这件事

在 Linux/嵌入式里，系统调用失败是常态而不是意外：磁盘满、资源暂时不可用（EAGAIN）、被信号打断（EINTR）、对端断开（EPIPE）。不判返回值等于把错误静默吞掉，线上问题最难查的就是这种——程序没崩，行为却不对。

目标两条：① 统一日志分级（一眼看出严重程度），② 每个系统调用返回值都判错（失败必有反应）。

§2 日志分级

2.1 级别怎么定

级别数值典型用途Release 版
DEBUG0变量值、流程细节裁剪掉
INFO1正常里程碑（启动、连接建立）保留
WARN2可恢复异常（重试、丢弃）保留
ERROR3本次操作失败保留
FATAL4致命，准备退出保留

约定：数值越大越严重，过滤条件是 level >= g_min_level。这样一条判断就能同时表达"打印哪些级别"。

2.2 编译期过滤（嵌入式常用）

DEBUG 日志在发布版不该占空间，用宏在编译期裁剪，比运行期判断更彻底：

#define LOG_LEVEL 2            /* 编译期可改：低于此值整段不进二进制 */

#define LOG(level, fmt, ...)                                  \
    do {                                                      \
        if ((level) >= LOG_LEVEL) {                           \
            log_emit((level), __FILE__, __LINE__,             \
                     __func__, (fmt), ##__VA_ARGS__);         \
        }                                                     \
    } while (0)

要点：do { ... } while (0) 让宏在 if/else 里当单条语句用；##__VA_ARGS__ 支持可变参数；自动带上 文件 / 行号 / 函数名，否则日志定位全靠猜。

2.3 本工程现状

已有一条 RT 安全日志通道 [agv_log_rt()](file:///home/zcy/Project/panasonic_canopen_agv/CO_application.c#L58-L78)，级别字段是 [agv_logrec_t.level](file:///home/zcy/Project/panasonic_canopen_agv/agv_queue.h#L28-L32)，目前只有 0=INFO 1=WARN 2=ERR。改造方向：把这里的 level 换成上面的 5 级枚举，日志宏统一走它，就不必到处裸调 printf。

为什么日志还要走队列？ RT 线程里绝不能做阻塞 IO。日志宏只负责"格式化 + 入队"，真正的写终端交给工作线程——这条链路已经建好，直接复用。

§3 系统调用的返回值约定

判错前必须先知道"失败长什么样"。不同 API 的失败信号不一样，别用一套模板套所有函数：

返回约定典型函数怎么判失败错误在哪
返回 -1open/read/write/ioctl/socket/close== -1errno
返回 NULLmalloc/calloc/strdup/fopen== NULLerrno（malloc 会置 ENOMEM）
返回 0 成功 / 非 0 错误码pthread_*（create/mutex_init…）!= 0返回值本身，不设 errno
返回字节数（可短）read/write/recv/send先判 -1，再判 < 请求长度短读≠错误，要循环补齐
最大的坑：pthread_* 不用 errno。失败时它直接返回错误码（如 EINVAL），errno 里是上次别的调用的残值。写 if (pthread_create(...) == -1) perror() 是错的——它返回的是正数错误码。

§4 errno 的用法与陷阱

  • 只在失败后立即读才有效。成功时 errno 可能残留旧值，不要拿它判断成功与否。
  • 会被后续调用覆盖。要留证据，失败后立刻存下来：int e = errno;。
  • 线程安全：errno 是线程局部存储（每个线程一份），多线程互不干扰——所以 worker 里用也没问题。
  • 转字符串：perror("open") 直接打；要拼进日志用 strerror_r()（strerror() 非线程安全）。

两个必须特判的错误

错误含义正确处理
EINTR被信号打断，操作没执行重试（慢速系统调用如 read/recv 会中招）
EAGAIN / EWOULDBLOCK非阻塞 fd 暂时无数据不是错误，回去等 epoll 通知，别报错

§5 判错姿势速查（本工程常用）

调用失败标志常见 errno处理动作
malloc / callocNULLENOMEM记录 + 清理已分配资源 + 返回错误
pthread_create!= 0EAGAIN/EPERM回滚已建线程，返回错误码
pthread_mutex_init!= 0ENOMEM/EAGAIN返回错误

close-1EINTR/EBADF不要重试（fd 可能已被复用），记日志即可
ioctl-1EINVAL/ENOTTY记录请求码 + 原因
socket / bind / connect-1EADDRINUSE/ECONNREFUSED记录 + 按策略重试或退出

§6 三种错误处理写法

6.1 嵌套 if（不推荐）

int r = a();
if (r == 0) {
    r = b();
    if (r == 0) {
        r = c();          /* 层数一多，缩进就失控 */
    }
}

6.2 goto cleanup（Linux 内核风格，推荐）

把"申请资源"和"释放资源"分成两段，任何一步失败就跳到对应的清理标签，只写一份清理代码：

int do_work(void)
{
    int ret = 0;
    char *buf = NULL;
    int fd = -1;

    buf = malloc(1024);
    if (buf == NULL) {
        ret = -ENOMEM;
        goto out;
    }

    fd = open("/dev/x", O_RDWR);
    if (fd == -1) {
        ret = -errno;                 /* 保存 errno 再跳 */
        goto out;
    }

    /* ... 正常逻辑 ... */

out:
    if (fd != -1)  close(fd);         /* 按申请逆序释放 */
    free(buf);
    return ret;                       /* 0 成功，负值错误码 */
}
为什么好用：资源释放只出现一次，不会漏；ret = -errno 把系统错误码统一成"0 成功 / 负值失败"，调用方判 if (ret < 0) 就够。

6.3 宏封装（可选）

#define CHECK(expr)                        \
    do {                                   \
        if ((expr) < 0) {                  \
            LOG(ERROR, "%s failed: %s",    \
                #expr, strerror(errno));   \
            goto out;                      \
        }                                  \
    } while (0)

适合重复度高的判错，但别滥用——宏里藏 goto 会降低可读性，团队约定好再用。

§7 错误码设计

  • 统一约定：0 = 成功，负值 = 失败。直接 return -errno 透传系统错误，语义清晰又不用自造码表。
  • 自定义错误用独立区段，避免和 errno 撞号：#define AGV_E_PARAM (-1000)、AGV_E_STATE (-1001)。
  • 不要用裸 -1 当内部函数返回：调用方拿不到"为什么失败"。要么返回 -errno，要么返回自己的错误码 + 单独输出。
  • 当前队列模块用的是 0 / -1（[agv_queue.h:53](file:///home/zcy/Project/panasonic_canopen_agv/agv_queue.h#L53)），简单够用；要更细时可升级为负错误码。

§8 日志和错误怎么配合

8.1 在哪一层记日志

原则：底层函数只返回错误，不刷日志；最外层（业务入口）带上下文记一次。否则一个错误从 open 一路往上返回，每层都打，日志立刻被刷屏。

层职责
底层（agv_queue 等）判错、返回错误码。不打印（最多 DEBUG）
中间层能补救就补救（重试/回退）；救不了就继续往上抛
入口层（app_programStart 等）记录一条 ERROR，带"做什么 + 哪个对象 + 为什么"

8.2 日志内容公式

/* 差：看不出上下文 */
LOG(ERROR, "failed");

/* 好：动作 + 对象 + 原因(errno 字符串) */
LOG(ERROR, "open(%s) failed: %s", path, strerror_r_safe(errno));

8.3 保留策略

环形队列满时是"丢最老的"还是"丢最新的"？当前实现是丢弃新日志 + 计数（[agv_queue.c:80-83](file:///home/zcy/Project/panasonic_canopen_agv/agv_queue.c#L80-L83)），好处是绝不阻塞 RT；代价是高峰会丢日志，所以用 dropped 计数 + drop=N 输出告知"这段日志不完整"。
