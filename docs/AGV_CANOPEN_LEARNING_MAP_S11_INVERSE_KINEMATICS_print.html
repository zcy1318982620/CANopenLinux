第 11 站 · 下行控制（下）：运动下发与差速逆运动学

本站定位：第 10 站让电机「能转」了——两个从站被推进到 Operation enabled，但轮速 0x60FF 恒为 0（安全起见没发运动指令）。本站补上最后一块：让车「会走」。做法是给上位机一个入口 cmd_vel（线速度 v + 角速度 ω），用差速逆运动学反解成左右轮目标转速，写进第 10 站已经建好的下行通道 0x60FF。

一句话概括：第 10 站回答了「电机凭什么能转」（使能时序），本站回答「车凭什么按你说的走」（(v,ω) → 两轮转速）。

为什么值得单独一站：① 这是 AMR/AGV 控制岗的「标准考点」——差速底盘的 v,ω ↔ 轮速 换算必问；② 它是「能看」（收位置）与「能控」（发速度）之间真正闭环的那一环；③ 做完本站，本项目就有了「上位机下指令 → 底盘动 → 里程计回读」的完整叙事。

阅读顺序：§0 地图 → §1 逆运动学（纯数学）→ §2 单位换算 → §3 cmd_vel 入口 → §4 模式选型 → §5 RT 拍落地 → §6 零硬件验证 → §7 小结。

§1 差速底盘：正解回顾与逆解推导

1.1 先回忆正解（第 7 站已落地）

第 7 站的里程计解的是正问题：已知左右轮各转了多远（dR/dL），求车体走了多远、转了多大角度。代码在 CO_application.c:479-480：

/* 第 7 站正解（已在跑）：两轮位移 → 车体位移/转角 */
double d   = (dR + dL) / 2.0;                 /* 车体前进量 */
double dth = (dR - dL) / ODOM_WHEEL_BASE_M;   /* 车体转角 */

把它写成速度形式（两边同除时间），就得到差速底盘的正解关系：

  v = (vR + vL) / 2          v  : 车体线速度 (m/s)
  ω = (vR - vL) / b          ω  : 车体角速度 (rad/s)
                             b  : 轮距（左右轮中心距，本工程 0.300 m）

1.2 逆解的推导：一个二元一次方程组

控制要解的是逆问题：已知想让车怎么走（v, ω），求左右轮各该多快（vR, vL）。把上面两个式子当方程组，联立解出 vR/vL：

  ① v = (vR + vL) / 2   →   vR + vL = 2v
  ② ω = (vR − vL) / b   →   vR − vL = ω·b

  ①+② :  2·vR = 2v + ω·b   →   vR = v + ω·b/2      ★ 右轮
  ①−② :  2·vL = 2v − ω·b   →   vL = v − ω·b/2      ★ 左轮

这是本站在面试里最该背下来的两行： vR = v + ω·b/2、vL = v − ω·b/2。
系数 b/2 的物理含义：车体绕中心旋转时，左右轮各在半径 b/2 处，速度 = 角速度 × 半径 = ω·b/2。左轮与右轮一正一负叠加在前进速度上。

1.3 三种工况的直觉校验

用公式验算三个典型动作，确认方向对不对（工程里这种「拿退化情形自检」的习惯很值钱）：

表 11-1 逆解的三种工况（取 v 前进为正、ω 逆时针为正，b=0.300）
工况输入 (v, ω)输出的两轮速度
直行v=0.2, ω=0vR = vL = 0.2 → 两轮同速同向
原地自转v=0, ω=1.0vR = +0.15, vL = −0.15 → 两轮等速反向，车原地打转
走弧线v=0.2, ω=0.5vR = 0.275, vL = 0.125 → 外侧轮快、内侧轮慢，向右画弧

符号约定必须全工程统一：ω 的正负、左右轮的编号、ODOM_DIR_R/L 的方向系数（CO_application.c:54-55）、以及里程计正解里的 dth=(dR−dL)/b，任何一处反号，车就会「越纠越偏」（正反馈）。上车前务必先用 §1.3 这种退化工况把符号对齐。

§2 单位换算：米/秒 ↔ 计数/秒

2.1 逆解的输入输出都是「米/秒」，但驱动器要「计数/秒」

逆解算出的 vR/vL 单位是 米/秒（轮面线速度）。但 0x60FF（目标速度）是驱动器自定义单位，大多数量产驱动器按编码器计数/秒或 rpm 解释。所以要补一步换算。

2.2 复用第 7 站的常数——正逆解天生对称

第 7 站里程计正解已经定义过一个常数 ODOM_K_PER_COUNT（CO_application.c:58）：「1 个计数 = 轮面走多少米」：

k = 2πr / N         r = 轮半径 0.050 m
                    N = 每转计数 10000（counts/rev）
→ k = 2π·0.050 / 10000 = 3.14159e-5  m/count

正解用它把「计数」乘成「米」，逆解自然就是把「米」除以它变回「计数」：

  0x60FF[counts/s] = vR[m/s] / k
                   = vR / ODOM_K_PER_COUNT

一个漂亮的对称：同一个 k，正解用乘法、逆解用除法，互为倒数。这保证了「发下去多少轮速」与「读回来多少位移」用的是同一把尺子——否则里程计和速度控制会各算各的，闭环永远对不上。

2.3 换算速查表（本工程标定值）

表 11-2 轮面线速度 ↔ 目标速度（r=0.050m, N=10000, k=3.14159e-5）
轮面线速度0x60FF（若单位=counts/s）等价转速（rpm）
0.05 m/s≈ 1592 counts/s≈ 9.5 rpm
0.20 m/s≈ 6366 counts/s≈ 38.2 rpm
0.275 m/s（弧线外轮）≈ 8753 counts/s≈ 52.5 rpm
1.00 m/s（满速）≈ 31831 counts/s≈ 191.0 rpm

若驱动器 0x60FF 用的是 rpm，则用另一条：rpm = vR · 60 / (2πr) = vR · 190.99（每 1 m/s ≈ 191 rpm）。

必须先确认真实单位：0x60FF 到底按 counts/s、rpm 还是 0.1rpm/其它，以驱动器手册/EDS 为准（森创一体机的对象字典里 0x60FF 的单位项会写明）。这和第 10 站的 COB-ID 一样，是「真机必须对齐、错了全盘皆输」的参数。零硬件阶段先按 counts/s 建模跑通逻辑，接真机时只改这一个换算系数。

§3 cmd_vel 从哪来：给对象字典加一个入口

3.1 现状：上位机只会「读」，不会「写」

第 8 站的 Qt 上位机（hmi/commworker.cpp:72）目前只做一件事：经 CiA-309 网关轮询读 0x6FFF 画轨迹。它没有任何「写」的路径，也就没法把 cmd_vel 送进来。

3.2 新增自定义对象 0x7000 agvCmdVel

照第 7 站 0x6FFF（里程计）的成法，再追加一个自定义数组对象，专门存放上层下发的期望速度：

表 11-3 新增对象 0x7000（与既有 0x6FFF 同构）
子索引名称类型含义 / 默认
0numberOfEntriesuint8= 2
1cmd_vfloat32期望线速度 v (m/s)，默认 0.0
2cmd_wfloat32期望角速度 ω (rad/s)，默认 0.0

方向：SDO 可写（ODA_SDO_RW），由上位机写；RT 拍读。用 float32 而非缩放整数，是为了和 0x6FFF 保持一致、省去定标换算。

追加位置有讲究：本工程的 ODList[] 按索引升序排列，OD_find 用二分查找；而 OD_ENTRY_H6FFF 被写死成 &OD->list[157]（OD.h:511）。因此新索引必须大于 0x6FFF 且追加到末尾，否则会让 list[157] 这个硬编码下标错位、牵连一堆引用。选 0x7000 正是为此（OD.c:2129-2131 的注释写明了这条规矩）。

3.3 跨线程读写：又要 CO_LOCK_OD

写侧在上位机 → 网关（main 线程），读侧在 app_programRt（RT 线程），两边访问同一片 OD_RAM——和第 7 站写 0x6FFF 是同一类竞态。所以读 0x7000 也要套 CO_LOCK_OD（可和第 10 站写 0x6040 合并进同一次临界区，减少加锁次数，见 §5.3）。

§4 模式选型：为什么是 0x6060 = 3

4.1 给速度，就得先选「速度模式」

CiA402 驱动器用 0x6060（Modes of operation）决定「你怎么理解我给的目标值」。本站下发的是轮速 0x60FF，对应的模式是 3 = Profile Velocity（PV，速度模式）。

表 11-4 常见 CiA402 模式（0x6060）与本工程取舍
值模式用哪个目标对象 / 是否采用
3Profile Velocity (PV)用 0x60FF 目标速度。本站采用——差速底盘给「轮子转多快」最直接。
1Profile Position (PP)用 0x607A 目标位置。适合「走固定距离」，需自带加减速规划。
8Cyclic Sync Position (CSP)用 0x607A，每周期给增量位置，实时性最高、实现最重。
9Cyclic Sync Velocity (CSV)用 0x60FF，周期性给速度，适合做闭环调速。

好消息：本工程字典里 0x6060 的默认值就是 3（OD.c:246，见第 10 站表 10-3）。也就是说驱动器上电默认就在速度模式，本站通常不必额外写 0x6060——除非你的机型默认不是 3。

4.2 若确实要写 0x6060：两条路

  • SDO 写一次（推荐）：模式是静态配置，开机设一次即可，不必每拍刷。用 SDO 写 0x6060 = 3（需网关/主站具备 SDO client 写能力）。
  • 加进 TPDO：若希望跟着控制字一起周期下发，可把 0x60600008（1 字节）追加进 0x1A00 映射。代价是每帧多 1 字节，且要重排映射项。

注意 0x6060 现在的处境：第 10 站的 TPDO 映射只含 0x6040 + 0x60FF（OD.c:148-158），没映射 0x6060。所以「靠写 OD 自动发出」这条路对 0x6060 不成立——要么走 SDO，要么显式加映射。别想当然。

§5 逆解落地：写进 RT 拍的哪一处

5.1 位置：紧跟第 10 站的使能推进之后

逆解的输入是「最新 cmd_vel」与「是否已使能」，两样都只在真节拍里才有意义。所以它放在 app_programRt、if (!timerEvent) return; 之后的真节拍段落，和第 10 站的 cia402_step、第 7 站的里程计积分同一层（CO_application.c:429-446）。

5.2 骨架代码

/* ===================== 第 11 站：差速逆运动学 + 运动下发 ===================== */

/* 从 0x7000 读 cmd_vel（float32×2）。跨线程，需锁。 */
static double cmd_v, cmd_w;
CO_LOCK_OD(co->CANmodule);
cmd_v = (double)OD_RAM.x7000_agvCmdVel[0];   /* 子索引 1 */
cmd_w = (double)OD_RAM.x7000_agvCmdVel[1];   /* 子索引 2 */
CO_UNLOCK_OD(co->CANmodule);

/* ① 逆解：车体 (v,ω) → 两轮轮面线速度 (m/s) */
double vR_ms = cmd_v + cmd_w * ODOM_WHEEL_BASE_M / 2.0;   /* vR = v + ω·b/2 */
double vL_ms = cmd_v - cmd_w * ODOM_WHEEL_BASE_M / 2.0;   /* vL = v − ω·b/2 */

/* ② 单位换算：轮面线速度 → 目标速度计数 (counts/s) */
int32_t vR_cnt = (int32_t)(ODOM_DIR_R * vR_ms / ODOM_K_PER_COUNT);
int32_t vL_cnt = (int32_t)(ODOM_DIR_L * vL_ms / ODOM_K_PER_COUNT);

/* ③ 安全门限：未使能 或 cmd_vel 超时失联 → 强制 0（见 §5.4） */
if (stR != 3 || stL != 3 || cmdTimedOut()) { vR_cnt = 0; vL_cnt = 0; }

/* ④ 写入 OD 目标速度：0x60FF。第 10 站已把它映射进 TPDO。 */
CO_LOCK_OD(co->CANmodule);
if (vR_cnt != OD_RAM.x60FF_targetVelocity) {
    OD_RAM.x60FF_targetVelocity = vR_cnt;
    OD_requestTPDO(OD_getFlagsPDO(OD_ENTRY_H60FF_targetVelocity), 0);  /* 见 §5.3 */
}
if (vL_cnt != OD_2nd_RAM.x60FF_targetVelocity) {
    OD_2nd_RAM.x60FF_targetVelocity = vL_cnt;
    OD_requestTPDO(OD_getFlagsPDO(OD_2nd_ENTRY_H60FF_targetVelocity), 0);
}
CO_UNLOCK_OD(co->CANmodule);

5.3 ⚠ 一个要提前处理的坑：0x60FF 现在触发不了 TPDO

第 10 站能给 0x6040「写完自动发出」，是因为给它挂了扩展，从而启用了 flagsPDO（见第 10 站 4.2 的说明：OD_getFlagsPDO 要求 entry->extension != NULL）。但 0x60FF 没有挂扩展，直接 OD_requestTPDO 不起作用。两条对策：

  • 方案 A（照搬第 10 站）：给 0x60FF 也挂一个「仅启用 flagsPDO」的扩展（read/write = OD_readOriginal/OD_writeOriginal），它就和 0x6040 一样「写即发」。
  • 方案 B（同步发送，更常规）：本工程 SYNC 是开着的（100 ms，CO_application.c:209）。把 TPDO 的 transmissionType 改成同步型（如 1 = 每个 SYNC 发一次），则轮速随 100 ms 节拍固定周期下发，不依赖「变化即发」。

怎么选：速度控制在多数 AGV 上就用同步 TPDO（方案 B）——周期确定、行为可预期。若想「只在变了才发」省带宽，用方案 A。两者都行，但别什么都不做：否则 0x60FF 只能靠 eventTimer 兜底（OD.c:120 附近，约 256 ms），对运动控制太慢。

5.4 产品级必须有的两条「保命逻辑」

  1. 未使能就不动：只有左右轮都到 Operation enabled（第 10 站的 stR==3 && stL==3）才允许输出非零轮速。否则按零。否则会出现「状态字还没爬到能转、速度命令却已经压上去」的失控隐患。
  2. 失联停车（deadman）：上位机若一段时间（如 500 ms）没刷新 cmd_vel，RT 侧必须自动把目标速度清零并可选报 EMCY。用一个「最近一次 0x7000 变化的时间戳/节拍计数」来判断即可。这是所有运动控制器的底线——没这条，上位机一崩，车不会停。

§6 零硬件验证：在 vcan 上跑通整条闭环

6.1 用第 10 站的「会回话」从站

第 10 站做了 tools/sim_motors_downlink.py：它收下行（0x50A/0x180 里的 0x6040+0x60FF），跑一个迷你 CiA402 状态机，再回发状态字到 0x38A/0x38B。本站正好复用它——因为它已经会「按收到的目标速度积分位置」，也就等价于「一台真的会转的电机」。

6.2 闭环自检：cmd_vel 出去，位姿回来

  ① 写 cmd_vel = (v=0.2, ω=0)   ──SDO──► 0x7000
  ② 逆解 ──► vR = vL = 0.2 m/s  ──► 0x60FF 两轮相同
  ③ sim 从站按 0x60FF 积分位置，回发 0x38A/0x38B
  ④ 主站里程计正解 ──► 0x6FFF 应呈「直线：x 增、y 不变、θ 不变」
  ⑤ 换 cmd_vel = (v=0, ω=1)     ──► 原地转：0x6FFF 的 θ 线性增长、x/y 近似不变

判据（把两条链对起来看）：cmd_vel 是逆解的输入、0x6FFF 是正解的输出。逆解 → 仿真 → 正解这一圈若能让「指令直线」走成「直线」、「指令自转」转成「自转」，就说明符号、轮距、单位换算全对了——这正是 HANDOFF 里说的「正逆闭环，看是否闭合」。

§7 小结与衔接

7.1 一句话链路

上位机写 0x7000(v,ω)（§3）→ RT 拍读并逆解 vR=v+ωb/2, vL=v−ωb/2（§1）→ 换算成 counts/s（§2）→ 安全门限（§5.4）→ 写 0x60FF 自动/同步发出（§5.3）→ 驱动器转 → 里程计正解回读（第 7 站）。至此「下指令 → 底盘动 → 回读」闭环成立。

7.2 读完应能回答

  1. 差速底盘逆解的两行公式是什么？（vR = v + ω·b/2，vL = v − ω·b/2）
  2. b 是什么？b/2 从哪来？（轮距；车体中心到单轮的距离，旋转时轮速=ω×半径）
  3. 为什么逆解用「除」ODOM_K_PER_COUNT，正解用「乘」？（两者互为倒数，共用一把尺子）
  4. 给速度该用哪个模式？用哪个目标对象？（0x6060=3 PV；0x60FF）
  5. 为什么新对象要用 0x7000 并追加到 ODList 末尾？（保持升序二分查找；OD_ENTRY_H6FFF=&list[157] 是硬编码下标，不能错位）
  6. 两条「保命逻辑」分别防什么？（未使能不动；cmd_vel 超时失联自动停车）
  7. 0x60FF 现在为什么触发不了 TPDO？怎么修？（未挂扩展=无 flagsPDO；挂扩展或改同步型 TPDO）

7.3 与下一站的衔接

本站让车「听指令走」，但还假设「总线永远好、从站永远在」。真实产品里，驱动器会掉线、会报故障。下一站 P1 心跳容错就把工程里「注册了却没用」的 HBconsumer（8 槽）真正用起来：给左右从站各配心跳监控，实现「心跳超时 → 判掉线 → 清零轮速（本站的 0x60FF）→ 报 EMCY → 尝试恢复」。注意它和本站天然咬合——掉线的第一动作就是本站的「失联停车」。
