§1 为什么需要队列：生产者-消费者模型

一句话结论：队列是解耦"干得快的人"和"干得慢的人"的缓冲区。生产者只管把活放进队列，消费者只管从队列取活；两边不必互相等待，速度不一致也不会互相拖累。

没有队列时，两个线程只能直接交接：生产者必须等消费者接手才能继续，消费者也必须等生产者送来才有活干，这叫紧耦合。有了队列，中间多了一个缓冲，双方各自按自己的节奏跑。

在嵌入式里，这个模型随处可见：

队列带来的三个好处：

  • 解耦：收发双方不需要知道对方是谁、跑得多快，只依赖队列接口。
  • 削峰：突发流量先堆在队列里，消费者按自己的能力慢慢消化。
  • 异步：生产者不必等处理完成就能返回，响应更快。
引用本工程：现在 RT 线程（rt_thread，见 [CO_main_basic.c](file:///home/zcy/Project/panasonic_canopen_agv/CO_main_basic.c#L885-L911)）在 1ms 节拍里直接 printf 打日志（[CO_application.c](file:///home/zcy/Project/panasonic_canopen_agv/CO_application.c#L247) 的 [RT] tick、[CO_application.c](file:///home/zcy/Project/panasonic_canopen_agv/CO_application.c#L309) 的 [ODOM]）。printf/fflush 会阻塞，等于把"慢消费者"的工作塞给了"不能慢的生产者"，破坏了实时性。正确做法：RT 线程只把日志入队，由消费者线程去打印。

§2 造队列的三个积木：互斥锁 / 条件变量 / 信号量

一句话结论：队列 = 一块共享内存 + 一把锁 + 两个"等待条件"。共享内存放数据，锁保证同时只有一个人动它，条件变量负责"空了就睡、来了就叫"。

2.1 互斥锁（pthread_mutex_t）：保证临界区互斥

队列的 buf/head/tail/count 是多个线程都会碰的共享数据，必须成对加解锁包起来，这段代码叫临界区。

pthread_mutex_lock(&q->lock);
/* 只有持有锁的线程能进这里 */
q->count++;
pthread_mutex_unlock(&q->lock);

要点：锁的粒度要小（只包真正共享的几行），但进入临界区后不要做耗时操作（不要在里面 printf、不要做 IO）。

2.2 条件变量（pthread_cond_t）：空了就睡、来了就叫

光有锁还不够：消费者发现队列空了，如果一直拿着锁空转，生产者永远拿不到锁，白烧 CPU。条件变量解决这个：条件不满足就释放锁并睡眠，被唤醒后重新拿锁继续检查。

/* 消费者: 队列空就睡在 not_empty 上 */
pthread_mutex_lock(&q->lock);
while (q->count == 0)                 /* 必须 while, 不能 if! */
    pthread_cond_wait(&q->not_empty, &q->lock);
/* 到这里 count>0, 说明有货了 */
pthread_mutex_unlock(&q->lock);

/* 生产者: 放进一条后叫醒一个等待者 */
pthread_cond_signal(&q->not_empty);

为什么用 while 不用 if被唤醒 ≠ 条件成立：可能"虚假唤醒"，也可能刚醒来条件就被别的线程抢走了。必须循环复查。

2.3 信号量（sem_t）：计数型同步

信号量是一个带计数的"通行证"：sem_wait 拿一张（计数为 0 就睡），sem_post 还一张（并叫醒等待者）。它的计数可以大于 1，所以能表达"最多允许 N 个并发"。

sem_t empty;   /* 空位数量, 初值 = 容量 */
sem_t full;    /* 已有数据条数, 初值 = 0 */

/* 生产者 */
sem_wait(&empty);   /* 没有空位就睡 */
/* ...写入数据... */
sem_post(&full);    /* 多了一条数据 */

/* 消费者 */
sem_wait(&full);    /* 没有数据就睡 */
/* ...读出数据... */
sem_post(&empty);   /* 多了一个空位 */
表 2-2　条件变量 vs 信号量：选哪个
维度条件变量信号量
本质等一个"条件表达式"等一个"计数 > 0"
配锁必须配互斥锁用自带原子计数，可独立用
表达能力可表达复杂条件（队列非空且未关闭）表达简单计数（还有几个空位）
典型用途队列空/满、线程池任务到达限制并发数、经典 P/V 生产者-消费者
怎么记：条件变量是"什么时候可以走"（配锁、配条件），信号量是"还有几个名额"（纯计数）。两个都能实现队列，本册 §4 用条件变量，因为它能把"未关闭"这个条件也一起判掉。

§3 队列的两种骨架：环形数组 vs 链表

一句话结论：追求性能用环形数组，追求动态规模用链表。嵌入式/RT 场景几乎都用预分配的环形数组——没有运行时内存分配，就不会有分配失败和分配延迟。

3.1 环形数组（ring buffer）

用 head（出队位置）、tail（入队位置）、count（当前条数）三个下标，在固定长度的数组上"绕圈"用。入队出队都是 (i + 1) % cap，O(1) 且不搬数据。

表 3-1　环形缓冲的下标规则
操作动作
入队buf[tail] = v; tail = (tail+1) % cap; count++;
出队v = buf[head]; head = (head+1) % cap; count--;
判空count == 0
判满count == cap

为什么额外用 count 而不是只靠 head == tail 判空/满？因为那样空和满的下标状态是一样的，分不清。带 count 最直观；另一种流派是故意浪费一个格子，用 (tail+1)%cap == head 判满。

3.2 链表队列

动态 malloc 每个节点，天然无容量上限。缺点：每入队一次就要分配一次内存（malloc 有不确定性，可能失败、可能加锁），在 RT 线程里是禁忌。适合非实时的普通业务队列。

选择建议：容量可预估（如日志、CAN 帧、任务）→ 环形数组，预分配、零分配、确定性；容量无法预估 → 链表。本工程该用环形数组。

§4 完整实现：阻塞有界队列（互斥锁 + 条件变量）

一句话结论：一个锁保护数据，两个条件变量分别管"满了别进"和"空了别出"。下面是最小可编译版本（存放 int，换成结构体同理）。

/* queue.h 结构定义 */
#include <pthread.h>
#include <stdbool.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    int             *buf;        /* 预分配的环形缓冲区 */
    size_t           cap;        /* 容量 */
    size_t           head;       /* 出队位置 */
    size_t           tail;       /* 入队位置 */
    size_t           count;      /* 当前条数 */
    pthread_mutex_t  lock;       /* 保护上面所有字段 */
    pthread_cond_t   not_full;   /* 生产者等这个: 不满时才可入队 */
    pthread_cond_t   not_empty;  /* 消费者等这个: 不空时才可出队 */
    bool             closed;     /* 关闭标志, 用于唤醒所有人退出 */
} queue_t;

int queue_init(queue_t *q, size_t cap) {
    q->buf = malloc(cap * sizeof(int));
    if (!q->buf) return -1;
    q->cap = cap;
    q->head = q->tail = q->count = 0;
    q->closed = false;
    pthread_mutex_init(&q->lock, NULL);
    pthread_cond_init(&q->not_full,  NULL);
    pthread_cond_init(&q->not_empty, NULL);
    return 0;
}

/* 阻塞入队: 满就睡在 not_full 上; 若队列已关闭返回 -1 */
int queue_push(queue_t *q, int v) {
    pthread_mutex_lock(&q->lock);
    while (q->count == q->cap && !q->closed)
        pthread_cond_wait(&q->not_full, &q->lock);
    if (q->closed) {                       /* 关闭时不再接收 */
        pthread_mutex_unlock(&q->lock);
        return -1;
    }
    q->buf[q->tail] = v;
    q->tail = (q->tail + 1) % q->cap;
    q->count++;
    pthread_cond_signal(&q->not_empty);    /* 叫醒一个消费者 */
    pthread_mutex_unlock(&q->lock);
    return 0;
}

/* 阻塞出队: 空就睡在 not_empty 上; 若"已关闭且取空"返回 -1 表示结束 */
int queue_pop(queue_t *q, int *v) {
    pthread_mutex_lock(&q->lock);
    while (q->count == 0 && !q->closed)
        pthread_cond_wait(&q->not_empty, &q->lock);
    if (q->count == 0) {                   /* closed && empty → 该退出了 */
        pthread_mutex_unlock(&q->lock);
        return -1;
    }
    *v = q->buf[q->head];
    q->head = (q->head + 1) % q->cap;
    q->count--;
    pthread_cond_signal(&q->not_full);     /* 叫醒一个生产者 */
    pthread_mutex_unlock(&q->lock);
    return 0;
}

/* 关闭: 唤醒所有睡着的线程, 让它们检查 closed 后退出 */
void queue_close(queue_t *q) {
    pthread_mutex_lock(&q->lock);
    q->closed = true;
    pthread_cond_broadcast(&q->not_full);  /* 必须 broadcast, 不能 signal */
    pthread_cond_broadcast(&q->not_empty);
    pthread_mutex_unlock(&q->lock);
}

void queue_destroy(queue_t *q) {
    pthread_mutex_destroy(&q->lock);
    pthread_cond_destroy(&q->not_full);
    pthread_cond_destroy(&q->not_empty);
    free(q->buf);
}

关闭为什么要 broadcast：睡着的线程可能有好几个（多个生产者/消费者）。signal 只叫醒一个，剩下的会永远睡着导致 join 卡死。关闭是"整体状态变化"，必须广播。

§5 RT 版：非阻塞入队（满则丢帧并计数）

一句话结论：RT 线程绝不能为了入队而睡眠，满了就丢、丢就计数。上面 queue_push 满时会睡，这在 RT 线程里不可接受——一睡就错过 1ms 节拍。RT 侧要用 try 版：拿不到锁或队列满都立刻返回，把帧丢掉并累加一个丢弃计数（用于事后观察丢了多少）。

#include <stdatomic.h>

/* 非阻塞入队: 满或拿不到锁 → 立刻返回 -1(丢帧), 绝不睡眠 */
int queue_try_push(queue_t *q, int v, unsigned *dropped) {
    if (pthread_mutex_trylock(&q->lock) != 0) {  /* 锁被占, 不等, 直接丢 */
        (*dropped)++;
        return -1;
    }
    int rc;
    if (q->count < q->cap && !q->closed) {       /* 还有空位 */
        q->buf[q->tail] = v;
        q->tail = (q->tail + 1) % q->cap;
        q->count++;
        pthread_cond_signal(&q->not_empty);
        rc = 0;
    } else {                                     /* 满: 丢弃并计数 */
        (*dropped)++;
        rc = -1;
    }
    pthread_mutex_unlock(&q->lock);
    return rc;
}
表 5-1　阻塞 push 与 try_push 的使用边界
版本用在哪
queue_push（会睡）普通业务线程：可以等，丢了数据更可惜
queue_try_push（不睡）RT 线程 / 中断相关：宁可丢一帧，也不能错过节拍

§6 无锁 SPSC 环形队列（单生产者单消费者）

一句话结论：如果生产者只有一个、消费者也只有一个，可以完全不用锁。因为"头"只有生产者改、"尾"只有消费者改，没有竞争，只需保证一个线程写完的数据，另一个线程能按顺序看见——用 C11 原子变量 + acquire/release 内存序即可。

#include <stdatomic.h>
#include <stdbool.h>

typedef struct {
    int           *buf;
    size_t         cap;    /* 容量, 取 2 的幂, 用位与代替取模 */
    size_t         mask;   /* cap - 1 */
    atomic_size_t  head;   /* 写位置: 只有生产者改 */
    atomic_size_t  tail;   /* 读位置: 只有消费者改 */
} spsc_t;

/* 生产者侧: 无锁 */
bool spsc_push(spsc_t *q, int v) {
    size_t head = atomic_load_explicit(&q->head, memory_order_relaxed);
    size_t next = (head + 1) & q->mask;
    size_t tail = atomic_load_explicit(&q->tail, memory_order_acquire);
    if (next == tail) return false;                    /* 满(牺牲一格) */
    q->buf[head] = v;                                  /* 先写数据 */
    atomic_store_explicit(&q->head, next, memory_order_release); /* 再发布 head */
    return true;
}

/* 消费者侧: 无锁 */
bool spsc_pop(spsc_t *q, int *v) {
    size_t tail = atomic_load_explicit(&q->tail, memory_order_relaxed);
    size_t head = atomic_load_explicit(&q->head, memory_order_acquire);
    if (tail == head) return false;                    /* 空 */
    *v = q->buf[tail];
    atomic_store_explicit(&q->tail, (tail + 1) & q->mask, memory_order_release);
    return true;
}
表 6-1　为什么 SPSC 能无锁（关键在"各改各的"）
变量谁写 / 谁读
head只有生产者写；消费者只读
tail只有消费者写；生产者只读
buf[]生产者写格子、消费者读格子，靠 release/acquire 保证顺序
内存序为什么这样写：release 保证"我前面写的 buf[head] 一定在我发布新 head 之前完成"；acquire 保证"我读到新 head 时，对应的 buf[] 数据也一定看得见"。少了它，编译器/CPU 可能重排，消费者就会读到旧数据甚至脏数据。
