Modbus 学习册：按岗位要求裁定的学习深度 + 落地到本项目

这份文档解决什么：你要学 Modbus，但"学到哪算够"没有标准答案。本册先**按你的岗位定位裁定学习深度**（避免又走进"自研协议栈"的坑），再给**够用的全部知识**，最后落到本项目的**真实产出物**：Modbus RTU IMU 主站。

依据：HANDOFF §16.1/§16.0 的岗位调研——校招线只要求"**了解**"工业总线；Modbus 在 AGV/工控**研发岗**是"熟悉/优先"，**只有"协议栈开发岗"才要求"从零搭建"**（且普遍 3 年+ 经验）。你是**校招 + 主控/应用向**，L3 刚好够"产出成果 + 面试能讲"，再深就越界。

§3 数据模型：四个区 + 地址编号

Modbus 把从站的数据摊成 4 个区，按"位/字"和"只读/可读写"两个维度划分。这是理解一切功能码的根。

表 3-1　Modbus 四区模型（★ = 本项目会用到）
区位宽 / 读写传统编号 / 协议偏移读 / 写功能码
线圈
Coils		1 bit，可读可写0xxxx（从 1 起）
PDU 内从 0 起		读 0x01／写单 0x05／写多 0x0F
离散输入
Discrete Inputs		1 bit，只读1xxxx
PDU 内从 0 起		读 0x02
输入寄存器 ★
Input Registers		16 bit，只读3xxxx
PDU 内从 0 起		读 0x04
保持寄存器
Holding Registers		16 bit，可读可写4xxxx
PDU 内从 0 起		读 0x03／写单 0x06／写多 0x10

头号地址坑：手册写"40001"，协议帧里是 0x0000；手册写"30001"，帧里也是 0x0000。即区号只是给人看的，帧里只发"区内的 0 基偏移"。换算：帧偏移 = 传统编号 − 区基数（4xxxx→减 40001，3xxxx→减 30001）。IMU 手册两种写法都可能出现，联调时先对齐这一点。

本项目怎么用：IMU 实时值（角度、角速度）放输入寄存器（只读，3x/0x04 读）；IMU 的配置项（零偏校准、量程、安装方向）放保持寄存器（可写，0x06/0x10 写）。这套分工是工业惯例，照着做面试也能讲。

5.2 CRC16（Modbus 版）算法

:  参数：多项式 0xA001（反射）、初值 0xFFFF、无最终异或
:  发送：CRC 低字节先发（如上例 0x0BC4 → 发 C4 0B）
uint16_t crc16_modbus(const uint8_t *buf, int len)
{
    uint16_t crc = 0xFFFF;
    for (int i = 0; i < len; i++) {
        crc ^= buf[i];
        for (int b = 0; b < 8; b++)
            crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : (crc >> 1);
    }
    return crc;
}
:  校验：对整帧（含末尾 CRC 两字节）再算一次，结果应为 0

5.3 切帧：为什么"静默间隔"是关键

RTU 帧没有长度字段，从站靠"总线静默"判断一帧结束。这决定了两件事：主站发送后必须等最后一个字节真正移出再动作；接收方要按字符间隔判断帧异常。

表 5-2　切帧时间与波特率（t = 1 字符含起始/数据/校验/停止位，按 8N1 = 10 位）
波特率t1.5（帧内间隔上限）t3.5（帧间静默）
9600≈ 1.56 ms≈ 3.65 ms
19200≈ 0.78 ms≈ 1.82 ms
38400≈ 0.39 ms≈ 0.91 ms
115200≈ 0.13 ms≈ 0.30 ms

串口参数（IMU 常见）：9600 或 115200、8 数据位、无校验(N) 或偶校验(E)、1 停止位 → 记作 8N1 / 8E1。以 IMU 手册为准，参数不匹配 = 全是乱码/CRC 错。

§6 Modbus TCP 帧格式（MBAP 头）

Modbus TCP 把 RTU 的"地址+CRC"换成了 7 字节 MBAP 头，其他（功能码、数据、异常码）与 RTU 完全一致。TCP 靠 TCP 保证完整性与顺序，所以没有 CRC。

表 6-1　MBAP 头（共 7 字节）+ PDU
字段长度取值 / 说明作用
事务标识符2 B主站自增（如 0x0001）把响应与请求对上号（并发时必需）
协议标识符2 B恒为 0x0000Modbus 专用；非 0 视为非 Modbus
长度2 B= 后续字节数 = 1 + PDU 长度有长度字段，所以不需要静默切帧
单元标识符1 B= RTU 里的"从站地址"网关后面挂串行从站时用；直连从站常填 0x01
PDU（与 RTU 相同）：功能码(1B) + 数据(NB)

示例：读保持寄存器，从站 1、起始 0、数量 2，事务号 0x0001：
00 01 00 00 00 06 01 03 00 00 00 02　（前 7 B = MBAP，"06" = 单元ID 1 + PDU 5 字节；无 CRC）

端口恒为 TCP 502。调试用 Wireshark 直接能解（内置 Modbus TCP dissector）。

从站处理不了时，把功能码最高位置 1（即 +0x80），再跟一个异常码：

表 7-1　异常码（够用即可，不必背全）

0x01ILLEGAL FUNCTION从站不支持该功能码IMU 不支持 0x10 → 改单写 0x06

主站必须处理异常，不能只看"没收到响应"。异常响应是正常帧（CRC 正确、有响应），只是功能码高位为 1。把异常当"丢包"重试，会永远重试下去。

§8 字节序：float32 跨两个寄存器（联调头号坑）

Modbus 只定义"16 位寄存器内部按大端传"（高字节在前）。但一个 float32 要占两个寄存器，这两个寄存器谁先谁后、字节怎么摆，协议没有规定——由设备厂商自定，于是有了 4 种排列：

表 8-1　float32 = 25.0（IEEE754 = 0x41C80000）的 4 种排法
名称寄存器顺序字节流口诀 / 常见于
ABCD大端（Big-endian）41 C8 00 00"先高字、再低字"；很多 PLC 默认
CDAB字交换（Word swap）00 00 41 C8最常见的"读出来是 0"元凶
BADC字节交换（Byte swap）C8 41 00 00部分国产仪表
DCBA小端（Little-endian）00 00 C8 41ARM 内存直出常见

怎么定这个坑：① 先查 IMU 手册（多半会写 "32-bit float, word order: low word first"）；② 查不到就用一个"已知值"校准——把 IMU 静止放平，看读回来的 4 字节能否还原成合理的 0/9.8/角度值；③ 代码里把"字序"做成一个配置项，联调时改一行就切。别硬编码。

int mb_open(const char *dev, int baud)      /* 开串口 + 8N1 + 可选 TIOCSRS485 */
{
    int fd = open(dev, O_RDWR | O_NOCTTY);
    cfmakeraw(&tio); tio.c_cflag |= CLOCAL | CREAD;      /* 原始模式 */
    cfsetispeed(&tio, B9600); cfsetospeed(&tio, B9600);  /* 以 IMU 手册为准 */
    tcsetattr(fd, TCSANOW, &tio); tcflush(fd, TCIOFLUSH);/* 上电清残帧(§9-④) */
    return fd;
}

int mb_read_input_regs(int fd, uint8_t addr, uint16_t reg, uint16_t n, uint8_t *out)
{
    uint8_t req[8]; int len = mb_build(req, addr, 0x04, reg, n);  /* 组帧+CRC(§5) */
    rs485_tx_enable();                    /* ① 切"发" */
    write(fd, req, len);
    tcdrain(fd);                          /* ★ 等最后一个字节真正移出(§9-①) */
    rs485_rx_enable();                    /* 切"收" */
    int r = wait_readable(fd, 300);       /* ③ 300ms 超时 */
    if (r <= 0) return -1;                /* 超时 → 调用方重试/判离线 */
    read(fd, resp, sizeof resp);
    if (resp[1] & 0x80) return -(resp[2]);/* ⑦ 异常码(§7)，负值返回 */
    if (crc16_modbus(resp, rlen) != 0) return -2;   /* CRC 校验 */
    memcpy(out, resp + 3, resp[2]);       /* 数据区(§5) */
    return resp[2];
}

float be_to_float32(uint16_t hi, uint16_t lo, int word_order)  /* ⑧ 字节序(§8) */
{
    uint8_t b[4];
    if (word_order == ABCD) { b[0]=hi>>8; b[1]=hi; b[2]=lo>>8; b[3]=lo; }
    else /* CDAB */         { b[0]=lo>>8; b[1]=lo; b[2]=hi>>8; b[3]=hi; }
    float f; memcpy(&f, b, 4); return f;
}

参考答案要点：1) 线圈(1b,RW)/离散输入(1b,RO)/输入寄存器(16b,RO)/保持寄存器(16b,RW)。2) 发 0x000A（40011−40001=10）；区号只是给人看的。3) 总线静默 ≥ t3.5。4) 0xA001、0xFFFF，低字节先发。5) 01 04 04 xx xx xx xx CRC（功能码+字节数4+4 字节数据+CRC）。6) 从站返回异常、异常码 0x02=非法数据地址；不能当丢包重试，要先修地址。7) 0x06 写单个、0x10 写多个；回显用于主站确认写入值一致。8) 多半是 float32 字序不匹配（§8 四种之一）；用已知值/静止态校准。9) 最后一个字节还在移位寄存器里，切收会截断响应首字节；应先 tcdrain() 等发完（或延时 ≥ t3.5）再切。10) Modbus 只有主站轮询、从站不能主动发；PDO 是主动/周期上报——实时推送场景该用 CANopen/EtherCAT。
