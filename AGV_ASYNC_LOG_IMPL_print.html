AGV 异步日志改造 · 代码梳理（精简）

工程：panasonic_canopen_agv ｜ 主题：RT 线程 printf → 有界队列 + 工作线程池

§1 改了哪里（一句话）

RT 线程（1ms 节拍）原来直接 printf + fflush，终端 IO 会拖慢节拍。现在 RT 里只做「格式化 + 非阻塞入队」，真正的写终端交给 2 个工作线程。

改前：RT 线程 → printf / fflush（阻塞写终端）
改后：RT 线程 → 有界环形队列 cap=256 → 工作线程池 ×2 → stdout

§2 新增/改动的文件

文件角色
agv_queue.h / agv_queue.c有界环形队列：非阻塞入队 + 阻塞出队 + 丢弃计数
agv_pool.h / agv_pool.c工作线程池：N 个常驻消费者循环 pop 队列
CO_application.c接线：启动/停止队列与线程池，RT 侧改调 agv_log_rt()
Makefile把 agv_queue.c / agv_pool.c 加进编译单元

§4 agv_queue：每个函数做什么

函数做什么传参返回
agv_queue_init 把 cap 向上取整到 2 的幂，分配环形数组，初始化锁与条件变量，计数清零 q 队列指针；cap 期望容量（<2 非法） 0 成功；-1 失败
agv_queue_destroy 销毁条件变量、锁，释放数组 q 无
agv_queue_try_push 非阻塞入队（RT 专用）：trylock 拿不到锁 / 队列满 / 已关闭 → 丢弃并 dropped++；成功则写入并 signal q；rec 待入队记录 0 成功；-1 丢弃
agv_queue_pop 阻塞出队（工作线程专用）：空则 cond_wait；关闭且取空返回 -1 让消费者退出 q；out 输出缓冲 0 取到；-1 已关闭且空
agv_queue_close 置 closed=1 并 broadcast 唤醒全部消费者 q 无
agv_queue_dropped 读取累计丢弃数（原子读，RT 可无锁调用） q 当前丢弃计数

§5 agv_pool：每个函数做什么

函数做什么传参返回
agv_worker（static） worker 主体：循环 agv_queue_pop，每条记录调一次 handler arg = 池指针 NULL（线程退出值）
agv_pool_create 分配池对象，创建 N 个 worker 线程；任一创建失败则回滚（close + join 已建线程 + 释放） nthreads 线程数；q 共享队列；handler 处理回调；user 透传参数 池对象指针；失败 NULL
agv_pool_destroy 优雅关闭：先 agv_queue_close（唤醒）→ 再 pthread_join 全部 worker → 释放 p 池指针 无
顺序铁律：必须先 close 再 join。worker 此刻正阻塞在 cond_wait，不 close 就 join 会永久卡死。

§6 CO_application.c 的接线

函数 / 位置作用
agv_log_to_stdout(rec, user) 工作线程里的处理回调：fputs + fputc + fflush 写 stdout，与改造前输出一致
agv_log_rt(level, fmt, ...) RT 专用：取时间戳 → vsnprintf 格式化 → agv_queue_try_push 入队。全程不睡眠
app_programStart 启动：agv_queue_init(&g_logq,256) → agv_pool_create(2, …) → g_log_ready=1
app_programEnd 停止：先 agv_pool_destroy 再 agv_queue_destroy（此时 RT 线程已被 join，无生产者）

RT 拍里原来的 printf 改成 agv_log_rt("...")，输出里带 drop=N 便于观测丢弃数。

§7 整个队列/线程池怎么跑起来

① RT 拍触发→② agv_log_rt 格式化→③ try_push 入队
↓ signal
④ 某 worker 从 cond_wait 醒来→⑤ pop 取出记录→⑥ handler 写 stdout
  • 正常路径：RT 入队成功 → 队列 signal → 2 个 worker 抢锁依次取走 → 各写各的 stdout。RT 全程不等 IO。
  • 队列满 / 锁被占：try_push 直接丢弃并 dropped++，RT 不阻塞，日志里 drop=N 随之增长。
  • 关闭时序：主线程先 join RT（生产者停）→ agv_pool_destroy 内部 close 唤醒 worker → worker 取空后 pop 返回 -1 退出 → join 全部 → 释放队列。

§8 几个容易踩的点

  • trylock 语义：拿不到锁就当失败丢弃，这是"宁可丢日志也不拖节拍"的取舍。
  • while (count==0 && !closed) cond_wait：用 while 防虚假唤醒，不能写 if。
  • 容量取 2 的幂，(tail+1) & (cap-1) 代替 % cap，省一次除法。
  • pushed / dropped 用 C11 _Atomic，RT 侧只做 atomic_fetch_add，读侧 atomic_load，不上锁。
  • 销毁顺序不能反：先 close（broadcast）再 join。
